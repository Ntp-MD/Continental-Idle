# Research file — Domain AC: Fire-safety and egress quantification (performance-based arithmetic)

Domain: **egress demand arithmetic, flow and level of service, ASET/RSET time budgeting, smoke and tenability arithmetic, and the design levers that buy quantified margin.** This is the **quantification layer under the prescriptive layer.** `building-codes.md` owns the limits — load factors (CODE-01), exit counts (CODE-02), common path (CODE-03), width per occupant (CODE-04), corridor width (CODE-05), dead ends (CODE-06), travel distance (CODE-07), remoteness (CODE-08), refuge (CODE-12), compartments (CODE-13/CODE-15), high-rise (CODE-17), round-up (CODE-27), floors-not-targets (CODE-28); `human-behavior.md` owns normal-operation flow, LOS and queues (HB-01…HB-03, HB-10, HB-13); `multi-scale.md` owns the core and portal queues (MS-08/09/10/21/23); `architecture-theory.md` TH-12 owns egress width as a programme task. **No rule here restates those numbers as a rule** — a prescriptive value appears only as a *named input*, cross-referenced by ID.

Added is the arithmetic that answers what a code table cannot — **does this plan have time, and how much?** demand → per-component capacity and which binds → `RSET = detection + notification + pre-travel + movement` → `ASET` against tenability criteria → the comparison with a stated margin and an uncertainty band → levers ranked by minutes bought per tile or per dollar.

**Boundary discipline.** A performance-based calculation is **not** a code allowance: `ASET > RSET` computed here does not substitute for a prescriptive route unless the adopting jurisdiction provides a performance-based option and names it. Conversely a code floor is not a target (CODE-28). Every figure carries document + jurisdiction + edition + clause and a tier; anything unread is written `NEEDS VERIFYING:` with the retrieval target named, and a caveat stays inside the rule that uses it.

Host grid (task-verified): 1 tile = 0.5 m; one independent 2D grid per floor; `walkable | blocked | door`; A\* movement, diagonals only when both neighbours are open (a 1-tile corridor is strict single file); vertical links are lift/stair **portals with a 30 s queue**; the sim carries **no egress traffic on stairs** (CODE-09/CODE-23 gap); no heights, volumes, temperatures or air. The smoke half of this file is therefore a **calculated-externally** layer whose grid-side inputs are named in FQ-24.

Derived grid constants (arithmetic, not claims): 1 tile = 0.5 m, 0.25 m², 4 tiles/m², 2 tiles = 1.0 m. Specific flow `s` (p·m⁻¹·s⁻¹) → persons/min per tile of width = `s × 30` (1.0 → 15 p/min/tile). Density `k` (p/m²) → tiles/person = `4/k`. Identity `s = k·v` — reject any triple that breaks it.

## Rules

### FQ-01 Run egress as a time budget, not a width check
- Rule: Every width/count/distance rule is a proxy for one inequality, `ASET > RSET`. Quantify both sides, decompose RSET into named terms, report the residual as a margin with a band. Passing at zero margin is the failure this rule exists to catch.
- Evidence: C/VM2 Clause 4.2 — "Demonstrate ASET >RSET for any rooms or spaces that can hold more than 50 people…" — and Clause 3.2, which gives Eq 3.1 `RSET = (td + tn + tpre) + (ttrav or tflow)` with Clause 3.2.4's "the greater of these two times is the evacuation time from the space". Corroborated as a requirement in **Australia**: "ASET must be greater than the RSET."
- Source: NZ MBIE, *Verification Method C/VM2 "Framework for fire safety design"*, Amendment 3 dated 19 Dec 2013 (base: Dept of Building and Housing, 10 Apr 2012), Clauses 3.2 (Eq 3.1), 3.2.4, 4.2 — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government** — jurisdiction **NZ**; + NCC 2019 Vol. One Amdt 1, Schedule 7 *Fire Safety Verification Method* §1.5 — https://ncc.abcb.gov.au/editions/2019-a1/ncc-2019-volume-two-amendment-1/schedule-7-fire-safety-verification-method/15-fire — **T1 government** — **Australia** (T1 government ×2, 2 origins).
- Class: CODE REQUIREMENT (the pass criterion and the RSET decomposition are the prescribed method of C/VM2 Cl. 3.2/4.2 and NCC Sch 7 §1.5; the analysis frame around them is this file's)
- Scope: universal as an analysis frame; as a compliance route only where the jurisdiction offers one.
- Confidence: Strong for the method and the pass criterion.
- Grid translation: Emit `design_fire, td, tn, tpre, t_movement = max(ttrav, tflow), ASET, margin, band` plus the term the margin is most sensitive to; never emit "egress adequate". The grid can compute the RSET side; it cannot compute ASET at all (FQ-24), so the comparison is reported as one-sided, never as a pass.
- Exceptions / failure mode: Both sides are model outputs. C/VM2 concedes it "requires a deterministic ASET/RSET approach with additional checks and balances" because probabilistic tools were unfit for inclusion; the result is only as good as the design fire (FQ-12). The trade-off: a time budget costs a scenario and an hour; a width check costs minutes — only the budget prices a lever (FQ-16). Symptom: a floor signed off on a width check whose computed residual is zero.

### FQ-02 Take headcount from a named density or load factor, with jurisdiction and area basis
- Rule: Demand comes from a factor table, never from the people drawn. A code load factor (CODE-01) and a design density are different systems with different gross/net conventions; mixing them inside one calculation is a silent error.
- Evidence: C/VM2 **Table 3.1 "Occupant densities"** (m²/person), read verbatim: **Lobbies and foyers 1.0**; Reception areas 10; Dining/beverage/cafeteria 1.25; Restaurants, dining rooms 1.1; loose seating 0.8, loose seating + tables 1.1; shop spaces and pedestrian circulation incl. malls/arcades 3; standing spaces 0.4; bar standing 0.5 / sitting 1.0; dance floors 0.6; stadiums and grandstands 0.6; fixed seating "As number of seats"; offices 10; classrooms 2; **bedrooms/dormitories/hospital wards "As number of bed spaces and staff when appropriate"**; commercial kitchens 10; plant/boiler rooms 30; bulk storage 100; parking 50; airport terminal 10, check-in 1.4.
- Source: C/VM2 Amendment 3, Clause 3.1 + **Table 3.1 "Occupant densities"** — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government** — jurisdiction **NZ**.
- Class: STANDARD (a verification-method design-density table read from the NZ compliance framework — explicitly *not* a legal occupant load, see below)
- Scope: podiums, assembly, retail, mixed-use; sleeping floors derive from beds, not area. Jurisdiction: these rows are **NZ C/VM2 Amendment 3**, not a universal density set.
- Confidence: Strong for the rows quoted (read from the PDF text layer).
- Grid translation: `demand = area_m2 / density_row_value`, row named in the record; tile form `occupants = walkable_tiles × 0.25 / factor`; then `max(area-derived, programme-derived)`. A 250 m² foyer holding 500 people is being designed at 0.5 m²/person — a dance-floor row, not a lobby; flag it.
- Exceptions / failure mode: These are design densities, not legal occupant loads; a US reviewer expects IBC Table 1004.5 ft²/person (CODE-01). Do not convert one system into the other. The trade-off: over-stating demand costs area; under-stating invalidates the analysis — ambiguous use → take the denser row and log it. Symptom: a headcount "derived from the plan" that is really the number of chairs drawn, or a calculation that divides an IBC ft²/person factor into a metric tile area.

### FQ-03 Keep the count test, the capacity test and the separation test separate
- Rule: Three questions, three inputs. A lobby's *exit count* may be credited on its own load while its *capacity* must carry everything discharging through it; and two doors on one wall are still one route (FQ-20). One number for all three is how a 500-person podium passes on paper.
- Evidence: Exception 1 to §1006.2.1 — "The number of exits from foyers, lobbies, vestibules or similar spaces need not be based on cumulative occupant loads for areas discharging through such spaces, **but the capacity of the exits from such spaces shall be based on applicable cumulative occupant loads**"; §1006.2.1.1 — "**Three exits … from any space with an occupant load of 501 to 1,000. Four exits … from any space with an occupant load greater than 1,000.**"
- Source: WAC 51-54A-1006 (Washington State adopted IBC, *Number of exits and exit access doorways*), read verbatim from the state legislature text; WSR 23-23-106 effective 3-16-24 — https://lawfilesext.leg.wa.gov/Law/WAC/WAC%20%2051%20%20TITLE/WAC%20%2051%20-%2054A%20CHAPTER/ — §1006.2.1 Exception 1, §1006.2.1.1 — **T1 government** — jurisdiction **US (WA adoption, IBC 2021-line)**.
- Class: CODE REQUIREMENT
- Scope: atrium ground floors, hotel podiums, theatre foyers, mall courts, transit concourses. Jurisdiction: **US (WA-adopted IBC)** — US-specific structure; NZ/AU do not use this exception.
- Confidence: Strong for the exception and the 501–1,000 / >1,000 breakpoints. **This closes part of `CODE-02`**, whose ladder was recorded there as `UNVERIFIED … not a validator input`; the Table 1006.2.1 cells (≤49 and 50–500 bands, common-path column) were **not rendered** in the WA text → `NEEDS VERIFYING:` printed Table 1006.2.1.
- Grid translation: Two records per floor — `required_exit_count(own load, path limits)` (CODE-02/CODE-03) and `required_capacity(catchment)` — and never let the first discharge the second. Worked catchment: 18 guest floors × 60 keys × 1.5 persons/key = 1,620 guests + 15 night staff = **1,635** (night); daytime podium = 500 lobby + 600 amenity + ~300 guests present = **1,400** ⇒ >1,000 ⇒ four exits.
- Exceptions / failure mode: US-specific structure; NZ/AU do not use this exception, and the Table 1006.2.1 bands behind the count are only partly rendered (above). The trade-off: cumulative-load capacity puts 4–8 leaves on the most valuable face of the building. Symptom: a 500-person podium "passing" because its two lobby doors were sized to the lobby's own load while every upper floor discharges through them.

### FQ-04 Compute width from flow capacity; a door is leaves, not width
- Rule: Two capacity methods are live — per-occupant factor (static) and flow capacity (a rate). The rate method is grid-computable and exposes what the table hides: nominal width is not capacity (deduct boundary layers), and past a threshold width a door buys nothing — only leaves do.
- Evidence: C/VM2 Clause 3.2.5, **Eq 3.4**, read verbatim: `Fc = (1 − a·D)·k·D·We` persons/s, `D` = density near the constriction ("for doors, use 1.9 persons/m²"), `We` = measured width **minus boundary layer**, horizontal `k = 1.4`, `a = 0.266`; "**For doorway flows, the maximum flow rate is limited to 50 people per minute for each standard door leaf that has a self-closing device fitted. If there is no self-closing device, equation 3.4 shall be used with no upper limit.**" **Table 3.5** boundary layer per side: door/archway 0.15 m; corridor and ramp wall 0.20 m; stairway wall or side tread 0.15 m; railing/handrail 0.09 m; obstacle 0.10 m; wide concourse 0.46 m; theatre chairs/stadium bench 0.00 m. Cross-check input: CODE-04 (IBC 2021 §1005.3.1 stair 0.3 in/occupant `partial (T3)`; 0.2 / 0.15 tiers unverified) — **input only, not restated as verified**.
  Derived: s(D) = 1.4·D·(1 − 0.266·D) → D 0.5→0.61 | 1.0→1.03 | 1.5→1.26 | 1.88→1.32 (max) | 2.5→1.17
   p·m⁻¹·s⁻¹. Critical density D* = 1/(2a) = 1.88 p/m²; s_max = k/(4a) = 1.32 = 79 p/min per effective m.
   The tabulated door density (1.9) IS the curve's maximum: the model queues doors exactly at capacity.
   Leaf crossover 1.32·We·60 = 50 ⇒ We = 0.63 m ⇒ nominal ≥ 0.93 m is capped ⇒ capacity = 50 × leaves.
   Capacity by nominal width (2×0.15 m deducted, cap applied): 0.5 m → 9.5 p/min (single file, never an
   egress door — CODE-05); 0.6 m → 14; 0.75 m → 21; 1.0 m (2 tiles) → 55 → capped 50.
   Convergence (2 origins): IMO MSC.1/Circ.1238 Annex 1 Table 1.2 = 1.3 p/(m·s) corridors/doors (read in
   HB-02) vs 1.32 derived from a NZ government model — 2 % apart.
- Source: C/VM2 Amendment 3, Clause 3.2.5 — **Eq 3.4** and **Table 3.5** (T1, **NZ**), read verbatim — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government (NZ)** + corpus-internal partial (US): CODE-04 / IBC 2021 §1005.3.1 (T3 rendering, `partial`); IMO MSC.1/Circ.1238 Annex 1 Table 1.2 as read in `human-behavior.md` HB-02 (T1, maritime).
- Class: CODE REQUIREMENT (Eq 3.4 and the 50 p/min leaf cap are prescribed by C/VM2 Cl. 3.2.5; the derived crossover arithmetic is this file's)
- Scope: every component with a width. Jurisdiction of the numbers: **NZ C/VM2 Amendment 3**; the US per-occupant alternative is a labelled cross-check input only (CODE-04).
- Confidence: Strong for Eq 3.4, Table 3.5, D = 1.9 and the 50 p/min cap.
- Grid translation: Per component emit `We`, `capacity_p_per_min`, `t_component`; report the binding element. The engine can compute `We = n×0.5 − Σ boundary layers` and `capacity = min(1.32·We·60, 50 × leaves)` directly from the tile run; it must not claim uncapped capacity from width alone, since the 50 p/min leaf cap is a rate limit no plan geometry removes.
- Exceptions / failure mode: Hydraulic — steady homogeneous stream, no counter-flow; invalid once the queue backs into the upstream space (re-solve the chain). The cap is for manual self-closing side-hinged leaves; automatic sliding doors take the open effective width. The trade-off: the cap makes a wide leaf wasted area; and because self-closers are the rated doors (CODE-25), the capped kind is the one you always have. Symptom: a 2.0 m "high-capacity" lobby door credited with double the flow of a 1.0 m leaf when both are capped at 50 p/min.

### FQ-05 Take pre-travel time from a table keyed to use, familiarity, care and alarm type
- Rule: Pre-travel is usually the largest RSET term and the one designers invent. It is set by sleep state, familiarity, care dependency **and what the notification device says**. Use the row, name it, apply it to the worst-affected group; where a method publishes percentiles, sum the tails it asks for rather than averaging.
- Evidence: C/VM2 **Table 3.3 "Pre-travel activity times"** (s), read verbatim: awake/alert **familiar** (offices, warehouses not open to public) origin **30**, remote **60**; awake/alert **unfamiliar** (retail, exhibition, restaurants) origin **60** / remote **120** standard signal, origin **30** / remote **60** **voice alarm**; **sleeping familiar** (apartments) 60 / **300** standard; **sleeping unfamiliar (hotels and motels)** origin **60**, remote **600** standard / remote **300** **voice alarm**; awake under care of trained staff 60/120; early childhood 60 s staff response then 60 s per child per staff (FQ-19); sleeping under care — FQ-19; **focused activities (cinemas, theatres, stadiums) space of origin 0**, occupants starting after detection+notification "or when fire in their space reaches **500 kW**, whichever occurs first". Distribution method, separate origin — **PD 7974-6:2004** Table 1 as reproduced by Fleischmann: organised by state/familiarity (A awake+familiar, B awake+unfamiliar, C sleeping: Ci dwellings, Cii managed occupancy, Ciii "**Sleeping and Unfamiliar (e.g. hotel, boarding house)**", D medical care, E transportation) and scaled by movement mode M1–M3, wayfinding complexity B1–B3 and alarm type A1–A3, with adders ("For B2 (Cinema, theater) add 0.2 for wayfinding. For B3 add 1.0"), the note "M1 would normally require voice alarm/PA", footnote a "**Total pre-movement time = Δtpre (1st percentile) + Δtpre (99th percentile)**", footnote b "These times depend upon the presence of sufficient staff", and the split "Δt_pre … includes two components: time for the occupant to **recognize** the alarm and time for the occupant to **respond**".
- Source: C/VM2 Amendment 3, Clause 3.2.3 + **Table 3.3 "Pre-travel activity times"** (s) — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**; + distribution method, separate origin: UK BSI **PD 7974-6:2004** Table 1 as reproduced by Fleischmann (T2, FQ-17) — https://ir.canterbury.ac.nz/bitstreams/084a6691-bb70-419b-9dcf-9e3044505f0e/download — **T2 university reproducing a standards-body document not read**.
- Class: CODE REQUIREMENT (the C/VM2 rows are the prescribed design values; the PD 7974-6 percentile convention is a method read second-hand)
- Scope: all RSET estimates; the staff footnote is decisive in healthcare and childcare. Jurisdiction: the tabulated seconds are **NZ C/VM2 Amendment 3**; the PD 7974-6 structure is UK-derived and reached only through a T2 reproduction.
- Confidence: **Strong** for every C/VM2 value; **Medium** for the PD 7974-6 structure — its per-cell minute values were **not transcribable** (the repository PDF lost the column headers) → `NEEDS VERIFYING:` PD 7974-6:2004 Table 1 with its percentile columns before quoting any PD minute value.
- Grid translation: Bind row = f(occupancy, familiarity, care, alarm spec); unspecified alarm → the standard-signal row plus a flag; emit `tpre` and the row label. Never present a point value as a median. The engine can select and apply a row from the programme's room labels and the alarm spec; it cannot observe familiarity or staffing, so both must be declared inputs.
- Exceptions / failure mode: C/VM2 gives point values with no distribution and puts its conservatism elsewhere: "the incipient phase of the fire growth has not been considered in the design fire. This provides an implicit safety factor for the pre-travel activity time." Percentile sums are a conservative convention, not a statistic — never convert to a mean. SFPE literature (paywalled) publishes longer night values. The trade-off: **alarm type is a services decision that moves hotel RSET by 300 s at zero plan cost** — the cheapest margin in this file (FQ-16). Symptom: an invented "60 s" hotel pre-travel with no named row, or a sleeping-unfamiliar value quoted without its alarm type.

### FQ-06 Use the sourced speed–density relation and the 1.2 m/s cap
- Rule: Travel time is `L / S(D)` and `S` falls with density. Free-flow speed on a full lobby overstates throughput; a single hand-drawn walking speed hides the coupling that makes plans fail.
- Evidence: C/VM2 Clause 3.2.4: `S = k − a·k·D` (Eq 3.2), `a = 0.266`, horizontal `k = 1.4`, "**with a maximum travel speed of 1.2 m/s**"; `ttrav = Ltrav/S` (Eq 3.3); `Ltrav` by summing room length + width, or "the measured length around obstructions if this is known". **Table 3.4** as read: corridor, aisle, ramp, doorway k 1.40 / 1.19 m/s; stairs by riser × tread — 191×254 mm k 1.00 / 0.85 m/s · 178×279 k 1.08 / 0.95 · 165×305 k 1.16 / 1.00 · 165×330 k 1.23 / 1.05.
- Source: C/VM2 Amendment 3, Clause 3.2.4 (Eq 3.2, Eq 3.3) + **Table 3.4** — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**.
- Class: CODE REQUIREMENT
- Scope: level travel, stair travel, doorway approach. Jurisdiction: the constants and the 1.2 m/s cap are **NZ C/VM2 Amendment 3**.
- Confidence: Strong.
- Grid translation: Evaluate `S` at design density, clamp to 1.2, emit the density used. Grid `L` = A\* tiles × 0.5 m is already the "around obstructions" measure — the better of C/VM2's two options. Derived: `S(D) = 1.4 − 0.3724·D` clamped → 0.5→1.20 | 1.0→1.03 | 1.5→0.84 | 1.88→0.70 | 2.5→0.47 m/s; a 20 m (40-tile) cross-lobby walk is 16.7 s free-flow and 28.6 s at queue density — 12 s of hidden time.
- Exceptions / failure mode: No counter-flow or turning; invalid above ~2.5 p/m²; the 1.4 m/s intercept is capped to 1.2 m/s by the same clause, so the intercept is a fit, not a walking speed; stair values need riser/tread geometry the grid does not model (CODE-09). The trade-off: 1.2 m/s everywhere is simple and optimistic; the curve is honest but needs density, i.e. iteration with FQ-07. Symptom: a travel time computed at 1.4 m/s — a value the clause itself forbids — or a walk timed at free flow that doubles once the population is on the floor.

### FQ-07 Solve the series: the binding component is the smallest capacity, not the narrowest corridor
- Rule: Occupants pass components in series, so time is set by the element with the lowest sustained capacity. Widening an element already 3× adequate changes nothing — and the mirrored error, banking door leaves behind a narrow corridor, is just as common and cheaper to miss.
- Evidence: The series is C/VM2's own construction — Eq 3.1 adds the components, Eq 3.4 gives each component a sustained capacity, so the discharge time is set by the smallest sustained capacity in the chain. Method corroborated corpus-internally by `human-behavior.md` HB-02 ("report the binding element per route") and HB-10 / FL-17 for queue formation at portals.
  Podium, 1,400-person daytime catchment: door bank 8 capped leaves = 400 p/min (3.5 min); corridor 3 tiles
   (1.5 m, We = 1.10 m) = 1.10 × 1.32 × 60 = 87 p/min → 16.1 min ← BINDS; stairs (FQ-09) 134 p/min.
   Realising 400 p/min needs We ≈ 5.06 m ⇒ ~5.5 m nominal (11 tiles, not 3). Demanded corridor specific
   flow = 6.67 p/s ÷ 1.10 = 6.06 p·m⁻¹·s⁻¹ against 1.32 achievable ⇒ saturated at ≈1.9 p/m², 0.69 m/s,
   LOS F. Leaves 9–12 buy 0 s.
- Source: C/VM2 Amendment 3, Clauses 3.2.4/3.2.5 with Eq 3.1 and Eq 3.4 — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ** (FQ-04/FQ-06) + corpus-internal method: `human-behavior.md` HB-02, HB-10, FL-17.
- Class: DESIGN PRINCIPLE (an arithmetic consequence of the sourced flow equations plus the corpus queue method — no clause states "binding component")
- Scope: the chain room → door → corridor → stair/portal → discharge.
- Confidence: Strong.
- Grid translation: Compute `capacity_p_per_min` per component, sort ascending, emit `binding_component`, and reject revisions that add width to a non-binding component. Every term here is grid-expressible (tile runs, leaf counts, A\* lengths); what the engine must refuse is any claim that adding width improved flow when the binding component did not change.
- Exceptions / failure mode: The series bound assumes a decoupled queue; in a deep building release is sequential, so it brackets rather than answers (FQ-18, FQ-24). The trade-off: capacity converts to seconds only at the binding element; elsewhere tiles are spent for nothing. Symptom: a design review that buys four more door leaves and gains 0 s because the corridor still binds at 87 p/min.

### FQ-08 Grade flow against a level-of-service band and name the system the letter comes from
- Rule: Specific flow and density are two faces of one curve joined by speed. "Wide enough" is not a property; a level of service is — but several incompatible band systems are published, so quote the band's own units and its source table, and verify `s = k·v`.
- Evidence: **Table 3**, "Walkway Level of Service (LOS) thresholds by space (m²/ped) and flow rate (ped/m/min)", **Fruin (1971)** column as rendered: B **3.2** m²/ped at **23** ped/min/m; C **2.3–3.2** at **23–33**; D **1.4–2.3** at **33–49**; E **0.9–1.4** at up to **82** (the render shows the E flow band as 66–82); F **0.5–0.9**, flow "var." (at capacity). **Table 9**, "Recommended HCM pedestrian LOS criteria for **stairs**" (the report states these "reflect ITE's flow values, **Fruin's (1971) original breakpoints for stairway level of service**"): A 1.9 m²/ped / 16 ped/min/m / 0.53 m/s / v/c 0.33 · B 1.6–1.9 / 16–20 / 0.53 · C 1.1–1.6 / 20–26 / 0.48 · D 0.7–1.1 / 26–36 / 0.42 · E 0.5–0.7 / **36–49** / 0.40 / v/c 0.73–1.00 · F **<0.5** m²/ped / **<0.40** m/s.
- Source: US FHWA / Volpe Center, *Capacity Analysis of Pedestrian and Bicycle Facilities* (FHWA-PD-96-001 / FHWA-RD-98-107), Section 3, **Tables 3 and 9** — https://www.fhwa.dot.gov/publications/research/safety/pedbike/98107/section3.cfm — **T1 US federal research report**, jurisdiction **US DOT**. Primary work Fruin, *Pedestrian Planning and Design* (1971) **not obtained** — these FHWA tables are its accessible T1 rendering. (HB-01 already carries the *HCM* space bands; this rule adds the **Fruin flow** bands and the **stair** bands, which HB-01 does not.)
- Class: STANDARD (published LOS band systems — a performance grading, not a regulatory limit)
- Scope: corridors, aisles, doors, stairs at design flow, normal and emergency. Jurisdiction: **US** federal research tables; the units are ped/min/m and m²/ped, not the NZ code's p·m⁻¹·s⁻¹.
- Confidence: Strong for printed values; **Medium** for letter-to-value mapping — the render merges the LOS A row with a boundary row and leaves a gap between D (49) and E (66).
- Grid translation: Emit `s`, `k`, `v` per component, assert `s ≈ k·v` within ±15 % (a violation means the numbers came from different systems), and label the band with its source table. Cross-validation (derived): at Fruin's walkway D/E boundary (1.4 m²/ped ⇒ k = 0.714 p/m²) the C/VM2 line gives S = 1.134 m/s ⇒ s = 0.81 p·m⁻¹·s⁻¹ = 48.6 ped/min/m against Fruin's printed 49 — two independent models 1 % apart, the best triangulation available without a laboratory.
- Exceptions / failure mode: **LOS bands measure comfort and route choice in ordinary walking, not survival.** Fruin's data are daytime, single-direction, smoke-free, and the F band (~1.1–2.0 p/m²) sits well below crush densities, so an LOS letter is never a life-safety criterion (FQ-10/FQ-11 do that job). Say which system — HCM, Fruin, or FHWA Table 4's recommended revision — a letter refers to. The trade-off: LOS C in a fire lobby costs real area; LOS E is legal and can triple flow time. Symptom: a report claiming "LOS D achieved" as if it were a fire-safety result, or a letter quoted with no named band system.

### FQ-09 Price the stair, and declare it off-model here
- Rule: The stair is the narrowest, slowest and most-shared element, and its capacity — not door width — is what a tower's escape time is made of. Width buys flow roughly linearly until a landing or door caps it; a second *remote* stair buys capacity and redundancy, which width never does.
- Evidence: three regimes pointing the same way: (1) C/VM2 Table 3.4 (T1, **NZ**; FQ-06) stair k 1.00–1.23, speeds 0.85–1.05 m/s vs level 1.40/1.19; (2) IMO *Guidelines for Evacuation Analysis* **MSC.1/Circ.1238** Annex 1 Table 1.2 (T1, **IMO/maritime**), read and cited in HB-02: maximum mass flow per unit width **level/doors 1.3, stairs down 1.1, stairs up 0.88 p·m⁻¹·s⁻¹**; (3) FHWA Table 9 (T1, **US**): stair LOS E **36–49 ped/min/m = 0.60–0.82 p·m⁻¹·s⁻¹**, the most conservative.
  Derived from Eq 3.4: max stair specific flow = k/(4a) = k/1.064 → k 1.00→0.94 | 1.08→1.01 | 1.16→1.09 |
   1.23→1.16 p·m⁻¹·s⁻¹ = 56 | 61 | 65 | 70 p/min per effective metre. A 1.4 m stair, walls both sides
   (We = 1.10 m) at k 1.08 → 67 p/min ≈ 1.3 capped leaves; 2 such stairs = 134 p/min ⇒ 1,635 night
   occupants ÷ 134 = 12.2 min of stair flow, before anyone starts walking (FQ-05). One stair for a tower
   is one doorway-wide stream for the whole building.
- Source: C/VM2 Amendment 3 **Table 3.4** — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government (NZ)**; IMO *Guidelines for Evacuation Analysis* **MSC.1/Circ.1238** Annex 1 Table 1.2 — **T1 intergovernmental (IMO/maritime)**, read and cited in `human-behavior.md` HB-02; US FHWA / Volpe Center FHWA-RD-98-107 Section 3 **Table 9** — https://www.fhwa.dot.gov/publications/research/safety/pedbike/98107/section3.cfm — **T1 government (US)**. (T1 government/intergovernmental, 3 origins.)
- Class: STANDARD (three published capacity regimes; reported as a band, no single regime is adopted here)
- Scope: any vertical escape. Jurisdictions of the three values: **NZ** (C/VM2), **IMO/maritime** (MSC.1/Circ.1238), **US** (FHWA/Fruin stair bands).
- Confidence: Strong that stairs are slower and lower-capacity; **Medium** on the value — the three span 0.6–1.2 p·m⁻¹·s⁻¹ across populations and geometries. Report the band, never a point.
- Grid translation: Use boundary-layer-deducted width, cite which regime's flow was used, and tag every stair result `OFF-MODEL (no stair traffic in host sim)`. Cross-ref MS-08, MS-21, FL-08. - Exceptions / failure mode: **not simulable here** — stairs carry no egress traffic on the host grid (`building-codes.md` discipline box, CODE-09, CODE-23). This is an off-model calculation: the grid supplies the inputs (effective width in tiles, storeys, population above) and cannot validate the result. A plan can look compliant because the lift portal absorbs flow a real evacuation may not have (CODE-23, fire recall). The trade-off: stair width costs core area on every floor; a second remote stair also answers CODE-08 and MS-21 and is usually the better purchase. Symptom: a tower "evacuating" through lift portals in the sim while the real stair — 12.2 min of flow for the night population — is never tested.

### FQ-10 Define ASET as "first criterion exceeded at 2 m", and expect visibility to bind
- Rule: ASET is not a fire-size number, it is the time until the *first* tenability criterion is breached at head height. Compute all of them, take the minimum, and name the binder: a visibility problem is a smoke-control problem, a dose problem is a time problem.
- Evidence: C/VM2 §3.5, verbatim: "ASET is defined as the time between ignition of the design fire and the time when **the first tenability criterion is exceeded** … The tenability parameters **measured at a height of 2.0 m above floor level**, as specified in NZBC C4.3, are: a) Visibility, b) FED(thermal), and c) FED(CO)." Comment: "**Visibility will generally be the first tenability criterion exceeded** in the calculations unless any exception is applied." NZBC C4.3 as quoted in Clause 4.2: occupants must not be exposed to "(a) a fractional effective dose of carbon monoxide greater than **0.3**; (b) a fractional effective dose of thermal effects greater than **0.3**; (c) … visibility is less than **10 m** except in rooms of less than **100 m²** where visibility may fall to **5.0 m**." Corroborated, separate origin: the same FED(thermal) > 0.3 and visibility < 10 m, assessed "at a height of 2 m above floor level".
- Source: C/VM2 Amendment 3 §3.5 + Clause 4.2 (quoting **NZBC C4.3**) — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**; + NCC 2019 Vol. One Amdt 1 Schedule 7 §1.5 — https://ncc.abcb.gov.au/editions/2019-a1/ncc-2019-volume-two-amendment-1/schedule-7-fire-safety-verification-method/15-fire — **T1 government**, **Australia** (T1 government ×2, 2 origins).
- Class: CODE REQUIREMENT
- Scope: every ASET side. Jurisdiction: the criterion set is **NZ (NZBC C4.3 via C/VM2)** corroborated by **Australia (NCC 2019 Sch 7 §1.5)**; both at 2 m.
- Confidence: Strong for the NZ/AU criterion set.
- Grid translation: `ASET = min(t_visibility, t_FEDthermal, t_FEDCO)` at z = 2 m, binder named. If only a layer height was computed, emit ASET = time for the underside to reach 2.0 m, labelled "geometry proxy; dose criteria not evaluated" (FQ-24). None of the three is computable on this host (no volumes, air or species) — the rule is a reporting contract for an externally evaluated ASET, never a grid calculation.
- Exceptions / failure mode: These criteria are **incapacitation-relative** and contain no temperature, radiant-flux, ppm, O₂ or HCl number. The circulated "10 m / 1 kW/m² / 60 °C / 4000 ppm / 15 % O₂" set is a different, SFPE-derived family (FQ-11); EA's note adds that FED = 1.0 "is considered the median value of a distribution, with one-half of the population being more susceptible", so a lower threshold suits at-risk groups. The trade-off: taking the minimum is conservative and shortens ASET; reporting only visibility is fast and can be unconservative near the plume. Symptom: an ASET quoted from visibility alone while a CO dose breaches earlier, or an SFPE-family number presented as the NZ/AU code criterion.

### FQ-11 Convert dose to concentration only with its exposure time; refuse unsourced limits
- Rule: Toxicity is concentration × time; a ppm limit without a duration is meaningless, and the conversion divides by the assumed exposure. The reciprocal duty: do not print a limit you cannot source.
- Evidence: §5.2 read verbatim: CO incapacitation "dose [ppm.min] … relatively constant … approximately **27,000 ppm.min**", so "just below **2,700 ppm** for a period of **10 minutes**" would not incapacitate but a spike above 2,700 reaches the criterion; convected heat = "the tolerance limit for a constant 10-minute exposure to **100 °C**", at **2.0 m**, air "conservatively assumed to be humid"; radiant = "severe skin pain threshold of **2.5 kW/m²**", which "generally may be reached when the hot layer temperature rises above **180–200 °C**"; §5.1 keeps the layer above head height; §5.3 uses FED per the SFPE handbook and **ISO 13571** with **FED = 1.0** = incapacitation, plus a "fractional effective concentration (FEC)" for irritants "including acid gases (**HF, HCl, HBr, SO₂, NOₓ**) and organic irritant gases (acrolein, formaldehyde, crotonaldehyde)" — **no numeric value given**. Fire-brigade limits (Table 1, after AFAC): routine 100 °C / 1 kW/m² / 25 min; hazardous 120 °C / 3 kW/m² / 10 min; extreme 160 °C / 4–4.5 kW/m² / 1 min; critical >235 °C / >10 kW/m² / <1 min. Origin of the code criterion FED < 0.3 + visibility 10 m: **UK BS PD 7974-6:2004**, reported by Fleischmann (T2, FQ-17), with the rationale that the underlying data "were for young healthy adult humans and animals which represent the least vulnerable population".
- Source: Society of Fire Safety NSW Chapter / Engineers Australia, *Practice Note for Tenability Criteria in Building Fires*, **Version 2.0 dated 3 April 2014**, §5.1–§5.4 incl. Table 1 (after AFAC) — https://www.engineersaustralia.org.au/sites/default/files/2024-01/tenability-criteria-practice-note_0.pdf — **T2 professional institution**, jurisdiction **Australia** (prepared under the BCA regime and stating it "may not be 100% applicable under building regulatory regimes in other countries"); + **UK BS PD 7974-6:2004** reported by Fleischmann (T2, FQ-17) — https://ir.canterbury.ac.nz/bitstreams/084a6691-bb70-419b-9dcf-9e3044505f0e/download — **T2 university** (T2 professional institution + T2 university, 2 origins).
- Class: DESIGN PRINCIPLE (a T2 practice note rendering paywalled SFPE/Purser material plus this file's refusal duty — the unsourced limits below are deliberately **not** given a STANDARD class)
- Scope: any ASET output quoting a concentration or temperature. Jurisdiction: the EA note is **Australian** (BCA regime); the code criterion it explains is UK PD 7974-6, adopted into NZ/AU as FED < 0.3 + visibility 10 m.
- Confidence: Medium-High — this renders paywalled SFPE/Purser material; the SFPE Handbook chapter itself was **not** read. Strong for what the T1 codes state. `NEEDS VERIFYING:` (a) "60 °C" — SFPE Handbook (Klote) or ISO 13571 with its duration; (b) "O₂ < 15 %" — ISO 13571 oxygen term (no code opened here uses an O₂ limit); (c) any HCl ppm — the FEC reference table; (d) ISO 13571 itself (paywalled). Those four are **excluded limits, not stated limits**: nothing in this list may be re-promoted to a tenability criterion until sourced.
- Grid translation: Emit `FED(t) = Σ cᵢ(τ)Δτ / Dᵢ` with dose basis and duration, or concentration with its exposure window. Any tenability row whose source column is empty prints `NEEDS VERIFYING` and is **excluded from the ASET minimum**, with the exclusion stated. The host computes neither dose nor concentration (no species, no air) — it can only enforce the sourcing contract.
- Exceptions / failure mode: **Do not merge the frameworks.** FED 0.3 (a code trigger) and 27,000 ppm·min (a median incapacitation dose) are different tests; 0.3 of that dose ≈ 8,100 ppm·min ≈ **810 ppm over 10 min**. And the stock "4000 ppm CO" is defensible only as a dose equivalent at ≤6.75 min (4000 × 6.75 = 27,000) — a qualifier almost never printed. The trade-off: a ppm-only limit is readable and wrong; a dose integral is correct and needs a time history. Symptom: an ASET table that quietly merges the NZ/AU code set with the SFPE/Purser set, or that reports 4000 ppm as a duration-free limit.

### FQ-12 Fix the design fire first, and price its uncertainty
- Rule: One input dominates the analysis — the HRR history. Use a jurisdiction-published growth rate, peak, yields and flashover rule, then report the margin at the design α **and at 3α**. A margin computed against the wrong α is not a margin.
- Evidence: C/VM2 Amendment 3 §2.3.1 + **Table 2.1** (T1, **NZ**), verbatim: "In most cases … the fire is assumed to grow as a **fast t² fire** up to flashover or until the HRR reaches the peak given in Table 2.1 or becomes ventilation limited." Table 2.1: all buildings (storage <3.0 m) growth **0.0469·t² kW**, **Ysoot = 0.07 kg/kg**, **YCO = 0.04 kg/kg**, CO₂ 1.5, H₂O 0.82 kg/kg, **ΔHc = 20 MJ/kg**, **radiative fraction 0.35**, peak **20 MW** or **500–1000 kW/m²** (CFD plan area); car parks (no stacking) **0.0117·t²**; storage 3.0–5.0 m **0.188·t²** with 50 MW, 1000–2500 kW/m²; storage >5.0 m **0.00068·t³·H** (H = stack height). §2.3.2: "Flashover is assumed to occur when the average upper layer temperature first reaches **500 °C**." Post-flashover yields **Ysoot = 0.14**, **YCO = 0.40**. Coverage evidence: Nilsson, Johansson & van Hees (Dept. of Fire Safety Engineering, Lund Univ.), *Fire Safety Science — Proc. 11th Int. Assoc. for Fire Safety Science Symposium*, pp. 517–530, 2014, DOI 10.3801/IAFSS.FSS.11-517 (T2, read this session): "designing for a fast fire growth rate of **0.047 kW/s² covers 97 % of accidental fires** (arson excluded) but only **91 % of all fires** (arson included)"; their Table 1 (after Holborn et al.) for public buildings: μ = −6.2, σ = 1.9, E(α) = 0.012, α₉₅ = 0.0463, α₉₉.₅ = **0.2711 kW/s²**, and 0.047 is the **89th** percentile for retail.
  Q = α t² ⇒ t = sqrt(Q/α). At α = 0.0469: 100 kW 46 s · 500 kW 103 s · 1 MW 146 s · 5 MW 327 s · 20 MW
   653 s. Times scale as 1/sqrt(α): α ×3 ⇒ ×0.577, i.e. a 3× growth-rate error removes 42 % of the
   pre-flashover clock; at α₉₉.₅ = 0.2711 the 1 MW milestone is 61 s, not 146 s.

- Scope: every ASET calculation. Jurisdiction: the growth rates, peaks, yields and flashover rule in Table 2.1 are **NZ C/VM2 Amendment 3**; the prescribed default is jurisdictional even though the same numeric "fast" constant circulates internationally.
- Confidence: Strong for the table and the percentiles; Medium for exporting α = 0.0469 (the *prescribed default* is jurisdictional even though 0.047 is the common "fast" constant).
- Grid translation: Record `alpha, peak_HRR, chi_r, Ysoot, YCO, dHc, flashover_rule` with the row cited, then emit the margin at α and at 3α — that pair *is* the uncertainty band. - Exceptions / failure mode: Α is a convention, not a measurement; ~1 in 11 all-fires exceeds a "fast" basis and ~1 in 200 public-building fires exceeds 0.2711 kW/s². The trade-off: a faster α is safer but costs area; the honest move is to price the sensitivity. Symptom: a comfortable margin computed against a growth rate no jurisdiction prescribed for it.

### FQ-13 Compute smoke production and layer descent from the fire — or state that you did not

Both are within reach at design time — but every assumption and every unverified coefficient must be printed with the result.

Source (equations): **not established.** The public rendering of the plume/layer working equations is US NRC **NUREG-1805 *Fire Dynamics Tools***, which returned **HTTP 403 on every attempt** this session (docs mirror and per-chapter URLs, two user agents), and the SFPE Handbook is paywalled.
  Worked (derived): 1 MW ⇒ fuel 1000/20,000 = 0.050 kg/s; soot 0.07 × 0.050 = 3.5 g/s; CO = 2.0 g/s. At
   the 20 MW Table 2.1 peak with post-flashover yields: soot 0.14 × 1.0 = 0.14 kg/s = 140 g/s — a 40× jump

### FQ-14 Detection and notification are designable minutes, not ambient assumptions
- Rule: `td` and `tn` are the first two RSET terms and are set by systems, not geometry. Detection comes from device response and threshold; notification is a policy default. For non-standard evacuation strategies (for example, management investigating sole activation), take account of the extended notification time."; §2.3.1 — sprinkler control keyed to "RTI, C-factor and activation temperature as specified in Table 3.2".

- Scope: every ASET/RSET case; detector spacing is a layout check the grid can run. Jurisdiction: the notification default and the device constants are **NZ C/VM2 Amendment 3**.

### FQ-15 Keep escape routes out of the radiant field; time-to-pain is closed-form
- Rule: A route can be tenable by smoke and dose and still unacceptable because it passes an opening the fire vents through. Radiation is a time comparison — time to pain must exceed time to pass — and both are computable at design time.
- Evidence: C/VM2 Amendment 3 §3.6 and §3.7 (T1, **NZ**), read: occupants egressing past a window "must not be exposed to a radiation level which will cause pain while evacuating. Therefore, the **time to onset of pain (t_p) must be longer than the exposure time (t_exp)**"; "all occupants must have evacuated past the window … **within 10 minutes after ignition** unless fire resisting glazing … is used"; "the maximum allowable radiation level that an occupant can be exposed to is **10 kW/m²**"; Eq 3.5 `t_p = (35 / q″_r)^1.33` s; Eq 3.6 `q″_r = F_w·ε·k·q″_w` with `q″_w` = **83 kW/m²** for FLED ≤400 MJ/m², **103** for 400–800, **144** for >800 MJ/m², ε = 1.0, k = 0.5 fire-resisting glazing / 1.0 otherwise, `F_w` the view factor at 2.0 m or glazing mid-height (lower) from the nearest required escape route; Eq 3.7 `t_exp = D/v` with **v = 1.0 m/s**, exposure counted only while incident radiation ≥ **2.5 kW/m²**. Exemptions: alternative route available; insulated fire-resisting glazing ≥ −/30/30; sprinklered buildings with purpose-designed window-wetting sprinklers on the fire side; openable parts must self-close on smoke/heat detection. "Analysis is not appropriate where occupants are likely to be mobility-impaired"; multiple openings need cumulative analysis (SFPE Engineering Guide on 1st/2nd degree burns). §3.7 permits the **point-source model with fixed radiation fraction** (Eq 3.8) for a burning object, limited to compartments whose average upper layer has not exceeded 150 °C.
- Source: C/VM2 Amendment 3 §3.6 (Eq 3.5 pain onset, Eq 3.6 radiant flux, Eq 3.7 exposure time) and §3.7 (Eq 3.8 point-source model, upper-layer validity limit) — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**; + the **SFPE Engineering Guide** on 1st/2nd degree burns, named in the clause for cumulative analysis of multiple openings (paywalled, not read — see **Sources**).
- Class: CODE REQUIREMENT
- Scope: routes past shopfronts and atrium glazing, external stairs and balconies beside unprotected openings, podium discharge beside a restaurant façade. Jurisdiction: every constant here is **NZ C/VM2 §§3.6–3.7**; the FLED bands feeding the wall-flux choice are FQ-22’s **NZ** table.
- Confidence: Strong for the equations and thresholds as read; the Eq 3.8 render was lossy (the constant **0.45** is legible) → `NEEDS VERIFYING:` Eq 3.8's printed term list. **Real tension inside one document:** Table 2.1 gives radiative fraction **0.35** while Eq 3.8 carries **0.45** — use the clause-specific value, never an average.
- Grid translation: For each route tile adjacent to an opening into a firecell compute `q″_r`, `t_p`, `t_exp`; fail if `t_p ≤ t_exp` or if the last occupant is still passing after 600 s; emit `OFF-MODEL` where mobility-impaired occupants use the route. Route length, tile distance and pass speed are plan quantities the grid has; the view factor is not — it needs a section the grid does not store, so it enters as a declared input with a stated basis.
- Exceptions / failure mode: The 10-minute window limits the method to early escape; the point source over-predicts near field and under-predicts at long range; the FLED bands come from FQ-22. The trade-off: the fix is usually a plan move (shift the route, make the wall solid); rated glazing costs money and transparency; wetting sprinklers remove the analysis but add a maintenance duty (FQ-16). Symptom: a route that "passes" the smoke and dose checks while running the whole population past an unprotected opening that vents the fire.

### FQ-16 Buy margin with systems before geometry, and quantify the purchase
- Rule: When margin is thin, order the options by minutes-per-cost. Sprinkler and voice notification change the analysis *inside* the verification method; extra width changes one term and usually not the binding one.

### FQ-17 Report the residual as a margin with a band, and call an inconclusive result inconclusive
- Rule: The test is `ASET > RSET`, but no opened authority fixes a numeric margin — the margin *is* the design's safety level, so it must be stated and justified. Where the margin is smaller than its own uncertainty band the result is **inconclusive**, not a pass, and the missing input must be named.
- Evidence: C. M. Fleischmann (University of Canterbury), *"Prescribing the input for the ASET versus RSET analysis: is this the way forward for performance based design?"* (conference paper, institutional repository, retrieved and read this session), abstract: "the Available Safe Egress Time (ASET) must exceeding the Required Safe Egress Time (RSET) **with an appropriate margin of safety**. Currently the necessary input and acceptance criteria are left up to the fire engineer with the approval from the authority having jurisdiction. Unfortunately the conventional guidance is **more qualitative rather than quantitative** which can lead to varying levels of safety in buildings depending on the values chosen" — its illustration: "in one building the designer evaluates the Fractional Equivalent Dose (FED) at 2 m above the floor yet in another design the Fire Engineer calculates the FED at 1.8 m". Same paper: NFPA 101 "lays out **8 scenarios** that must be used to evaluate a proposed building design" but they "do not provide quantitative advice about the design fire, acceptance criteria, or methodology". EA practice note §5: "**Factors of safety are not proposed within this practice note as these are expected to be developed and agreed upon on a project specific basis.**" C/VM2 prescribes the bare inequality with **no** numeric margin, substituting the §4.10 deterministic robustness check (applies where >150 people, or >50 in a sleeping firecell, or >20 detained/under care would be exposed) and an admitted "implicit safety factor" carried in the design fire (Clause 3.2.3).

### FQ-19 Model staff-assisted evacuation as a resource-limited queue
- Rule: When movement depends on a finite trained crew, evacuation time is `units × service_time / crew_pairs` and corridor width is irrelevant. This term dominates healthcare and childcare RSET and is the one most often omitted.
- Evidence: C/VM2 Amendment 3, Table 3.3 (T1, **NZ**), read: hospitals and rest homes (sleeping, under care of trained staff) — enclosure of origin "**60 s for staff to respond to alarm then 120 s (per patient per 2 staff)**", with note 2: "This allows 120 s to move each patient from their room to the next adjacent firecell. This includes time for staff to prepare the patient and transport them to the adjacent firecell, and then to return to evacuate another patient. The commentary document for this Verification Method gives details of staff to patient ratios."; remote **1800 s**; occupants not movable for a procedure — "**1800 or as per specific requirements, whichever is the greater**". Early childhood care: origin **60 s** then "**60 s per child per staff**" to an adjacent place of safety on the same floor; remote 120 s. Corroboration (T2, PD 7974-6 via Fleischmann): assisted times "depend upon the presence of sufficient staff".
- Source: C/VM2 Amendment 3, **Table 3.3** rows for hospitals and rest homes (incl. note 2) and early childhood care, plus the staff-dependency footnote of PD 7974-6 as reproduced by Fleischmann (T2; FQ-05/FQ-17) — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**; + https://ir.canterbury.ac.nz/bitstreams/084a6691-bb70-419b-9dcf-9e3044505f0e/download — **T2 university**.
- Class: CODE REQUIREMENT
- Scope: wards, theatres and recovery, restraint and therapy spaces, nurseries, any staff-mediated movement (CODE-24). Jurisdiction: the rates are **NZ C/VM2 Table 3.3** — Medium outside NZ (see Confidence).
- Confidence: Strong for both rates and the response allowances; Medium outside NZ; the staff-ratio commentary is a separate document → `NEEDS VERIFYING:` C/VM2 commentary staff:patient ratios.
- Grid translation: `t_staff = n_units × unit_time / n_crew`, in series with the unit's own travel time, per compartment for defend-in-place; emit `staff_shortfall = required_pairs − roster` as a REVIEW flag — an operationally unsafe plan can pass every width test (CODE-28). A 60-patient ward with 4 staff available = 2 pairs ⇒ 60 × 120 / 2 = 3,600 s = **60 min** to move the ward to the adjacent firecell — longer than the whole tower stair case in FQ-09; staffing is the design parameter, not the door. `t_staff` is arithmetic on programme counts (patients, children, crew pairs) and is fully computable at design time; what the engine must refuse is any inference of a roster from a plan — staff numbers are a declared operational input, and the shortfall flag is the deliverable.
- Exceptions / failure mode: Assumes a crew doing nothing else; ignores rosters, unrelated calls, unfamiliar patients. The "return to evacuate another patient" wording makes 120 s a **service time**, so the queue is sequential and parallelism is bounded by crew pairs. The trade-off: crew size divides RSET; width helps only if the queue binds (FQ-07). Symptom: a ward that passes every width and distance test with no crew to move the patients.

### FQ-20 Verify escape-route separation as geometry, with the population step it depends on
- Rule: Two exits a single fire can close are one exit. Separation is measurable on the grid — an angle to diverge at, a distance to reach — and the required distance steps with the population using the routes, so the same core can pass at 200 occupants and fail at 300.
- Evidence: C/VM2 Amendment 3, Clause 4.1 design scenario (**BE**, "Fire blocks exit"), jurisdiction **NZ**, read verbatim: applies to "escape routes serving **more than 50** people"; "Single escape routes are permitted to serve up to **50** people"; exception — it "does not apply to vertical stair enclosures serving not more than **150** people fire separated from all other parts of a building or, if the building is sprinkler protected, serving not more than **250** people"; and "In order to be regarded as alternative escape routes, the routes shall be separated from each other and shall remain separated until reaching a final exit. Separation shall be achieved by **diverging (from the point where two escape routes are required) at an angle of no less than 90°** until separated by: a) a distance of at least **8.0 m** when up to **250** occupants are required to use the escape routes or at least **20 m** when more than **250** occupants are required to use the escape routes; or b) Smoke separations and smoke control doors."
- Source: C/VM2 Amendment 3, Clause 4.1 design scenario (**BE**, "Fire blocks exit") — https://cdn.abcs.co.nz/resources/Archive/Redundant%202014/CVM2%202013%20Dec%2019%20Amend%203%20Protection%20From%20Fire.pdf — **T1 government**, jurisdiction **NZ**.
- Class: CODE REQUIREMENT
- Scope: every floor where two routes are required; the check is direct on the grid. Jurisdiction: the divergence angle and separation distances are **NZ C/VM2** — they are a different geometry from the US remoteness rule and are not interchangeable with it.
- Confidence: Strong as read; jurisdiction-specific.
- Grid translation: From the split point walk both routes; require bearing divergence ≥90° and straight-line separation ≥8 m (≤250 p) / ≥20 m (>250 p) sustained to final exit, or an explicit smoke separation with smoke-control doors along the shared stretch. Symptom: two doors on one wall credited as two routes, or a plan that satisfies the NZ divergence rule presented as satisfying a US diagonal test (or the reverse).

## Worked example: 21-floor hotel lobby

**Given.** 21 storeys: L1 podium lobby/foyer; L2–L3 restaurant + banquet; L4–L21 = 18 guest floors × 60 keys = 1,080 keys at 1.5 persons/key. Vertical: **2 stairs + 4 lifts**. Sprinklered and detected throughout (CODE-25 assumption, `partial` there). Alarm: conventional strobe/bell.

**1 — Demand (FQ-02).** Night: 1,620 guests + 15 staff = **1,635**. Daytime podium catchment: 500 lobby (at Table 3.1's 1.0 m²/person ⇒ 500 m² = 2,000 tiles) + 600 amenity (L2–L3 at 1.1 m²/person) + ~300 guests present = **1,400**.

**2 — Exit count (FQ-03).** Podium daytime 1,400 > 1,000 ⇒ **four exits minimum** (WAC 51-54A-1006 §1006.2.1.1, T1 US/WA). The lobby's *count* may be credited on its own load under Exception 1, but its *capacity* must carry the cumulative 1,400. `NEEDS VERIFYING:` Table 1006.2.1's ≤49 / 50–500 bands (not rendered in the WA text).

**3 — Required width, two methods (FQ-04).** US per-occupant input (CODE-04, `partial`): 1,400 × 0.2 in = 280 in = **7.11 m** level; 1,400 × 0.3 in = 420 in = **10.67 m** stair equivalent; rounded up per CODE-27 → 15 tiles and 22 tiles. NZ flow method (T1): each self-closing leaf = 50 p/min; a 2-tile (1.0 m) leaf gives We = 0.70 m ⇒ 55 → **capped at 50**. So the bank's real parameter is **leaves**. Eight leaves × 1.0 m = **8.0 m = 16 tiles** of door run — **within ~12 %** of the US figure; the agreement is the cross-check, not a licence to average the methods.

**4 — Series capacities and the binding element (FQ-07).** Door bank 8 leaves = 400 p/min (3.5 min); corridor 3 tiles (We 1.10 m) = **87 p/min → 16.1 min ← BINDS**; stairs 2 × 1.10 m (k 1.08) = **134 p/min**. The 8-leaf bank is stranded behind a 1.5 m corridor: realising 400 p/min needs We ≈ 5.06 m ⇒ **~5.5 m nominal (11 tiles)**. Either widen the corridor or cut the bank to 2 leaves; leaves 9–12 buy 0 s. Demanded corridor specific flow = 6.06 p·m⁻¹·s⁻¹ against 1.32 achievable ⇒ saturated at ≈1.9 p/m² (0.69 m/s), LOS F (FQ-08).

**5 — RSET with a band (FQ-01/05/09/14/18).** Night, tower descending: `td` ≈ 60 s (modelled from Table 3.2 devices, not computed — FQ-24); `tn` = 30 s (Cl. 3.2.2); `tpre` = **600 s** (sleeping + unfamiliar + remote + standard signal); movement = stair-limited 1,635 ÷ 134 = **733 s** (upper bracket, floors released in series).
`RSET_upper ≈ 60 + 30 + 600 + 733 = 1,423 s ≈ 24 min` · `RSET_lower ≈ 30 + 300 (voice row) + ~500 (partial parallel release, phased strategy) ≈ 830 s ≈ 14 min`.
Sensitivities: α ×3 ⇒ time to any HRR ×0.577 (ASET falls, RSET unchanged); stair flow across the three sourced regimes (0.6–1.2 p·m⁻¹·s⁻¹) moves the 733 s term to roughly 500–1,000 s.

**6 — ASET: not computed, and why.** The host grid has no volumes, air or species, so visibility, FED(thermal) and FED(CO) cannot be evaluated (FQ-24), and the plume/layer coefficients that would let an agent estimate descent are in a document that returned HTTP 403 all session (FQ-13). Under NZBC C4.4 a sprinklered space where ≤1,000 occupants can be exposed loses the visibility and thermal criteria — but this podium can expose **1,400**, so **no exemption applies** and all three criteria must be evaluated by a zone or CFD model of the FQ-23 scenario (fire in the L2 store or banquet kitchen, undetected, target = lobby filled to 500 at 1.0 m²/person).

**7 — Verdict (FQ-17).** **`margin: INCONCLUSIVE`** — the RSET side is quantified with a band (14–24 min); the ASET side does not exist yet. Required to close it: the two-zone/CFD run above, the verified plume coefficients, and the adopting jurisdiction's tenability set (FQ-10/FQ-11).
Firm results regardless of ASET: **four exits minimum, eight discharge leaves**; the **1.5 m corridor is the binding capacity** and widening it is the only geometry change that buys flow; the **voice alarm is worth 300 s** of a ~24-min RSET for the price of speakers (FQ-16); and the **stair — 12.2 min of flow — is off-model here**, so a plan that "works" because the lifts absorb the flow is unverified, not safe (CODE-09, CODE-23, FQ-09).

## Type-specificity audit

- **Universal (any occupancy):** FQ-01 (time budget), FQ-04/FQ-06 (flow, speed, effective width), FQ-07 (binding component), FQ-08 (LOS bands), FQ-10/FQ-11 (tenability and dose arithmetic), FQ-12 (design fire and sensitivity), FQ-17 (margin and inconclusive verdict), FQ-20 (route separation), FQ-24 (grid adapter and flagging).
- **Hospitality (hotels / R-1):** FQ-05's 600 s sleeping-unfamiliar pre-travel is the dominant term and no other occupancy carries such a reaction allowance as a *design number*; FQ-03's lobby-cumulative-capacity rule is the podium test; FQ-09's stair flow brackets tower RSET while the lobby doors look generous; FQ-23 applies the UT scenario to the L2 store/kitchen; FQ-22 prices sleeping spaces at 400 MJ/m² but restaurants and upholstered seating at 800, making the podium band change a plan decision; FQ-16's C4.4 relief is population-capped at 1,000 and a 1,400-catchment podium does not get it. *Divergence:* the human risk and the fire risk sit in different places — unfamiliar sleeping occupants far from the fire, and a fire far from the crowd. Kitchen/laundry/refuse rankings stay CODE-26 conventions (UNCITED), not quantified hazards.
- **Healthcare (I-2) — the largest shift:** FQ-19's staff-limited service rate (120 s per patient per 2 staff; 1800 s remote allowance) replaces the flow arithmetic as the governing term; FQ-18's strategy is horizontal defend-in-place to the next adjacent firecell; FQ-21's refuge carries the non-ambulant load; and the verified WA text exempts **Group I-2 and I-3** from the elevator-landing two-way communication requirement (§1009.8 Exception 6), changing *where* comms must sit. *Divergence:* width is rarely binding — crew and compartment count are; a pass in this file's arithmetic still cannot license a plan that assumes occupants self-evacuate (CODE-24).
- **Assembly / focused activity:** FQ-05 gives cinemas, theatres and stadiums **0 s** pre-travel with a 500 kW trigger, so they are movement-limited, not reaction-limited — FQ-04's leaf caps and FQ-07's series minimum dominate; C/VM2 Table 3.5 gives theatre chairs a **0.00 m** boundary layer, so seating rows lose no effective width, a genuinely different arithmetic from corridors.
- **Retail / malls / transit:** Table 3.1's low densities (3–10 m²/person) keep demand per m² small but unfamiliarity costs the 60/120 s rows; the wide-concourse boundary layer (0.46 m per side) is the one element that specifically penalises large open floors; and FQ-22's bulk-retail rule (800 MJ/m² per metre of storage height, minimum 2400) makes high shelving a structural and plan problem, not a merchandising one.
- **Storage, plant, parking:** the design-fire α changes with stack height (0.0117 car park → 0.188 for 3–5 m → 0.00068·t³·H above 5 m) — the only place in this file where stacking height directly sets ASET.
- **Offices / familiar occupants:** the smallest pre-travel (30/60 s) moves the whole margin question onto movement and ASET; FQ-21 and FQ-09 dominate where floors are elevated.

**Net for the design agent:** what a code table gives you is a *limit*; what this file gives you is *times and rates*, and only the second kind tell you whether a plan has margin. Compute the RSET side fully on the grid — demand, leaves, effective widths, series capacities, separation, staff-limited queues — state the design fire and its 3α sensitivity, and then report the ASET side as the named gap it is, with the model and the two coefficient sets required to close it.
