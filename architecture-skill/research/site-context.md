# Research file 04 — Site & context (Domain H): how the ground the building sits on constrains the plan

Scope: the operational knowledge an agent needs to place a building *on a site* rather than in
space — boundary and build envelope, access and entrances, vehicle and fire circulation, transit
and pedestrian proximity, planning parameters (FAR / coverage / impervious), topography, sun,
noise, privacy, microclimate, street-wall and density logic, phasing, and the difference between
site plan, footprint, floor plate and floor area.
Explicit split used throughout: **jurisdiction-dependent** numbers are stamped with the authority
and edition that publishes them and must be re-verified for the project's actual place; **transferable
principles** carry without a jurisdiction tag.

Host grid this file is written against:
`1 tile = 0.5 m` → `2 tiles = 1.0 m`, `1 tile = 0.25 m²`, `4 tiles = 1 m²`. One 2D grid per floor,
origin-aligned; tile states `walkable | blocked | door`. **No terrain, no section, no neighbouring
3D massing**, so every three-dimensional site factor is carried as a *grid attribute*: setback
tiles, entrance tiles, façade-aspect assignment, noise-source edge tag, slope-class tag, protected
open-space tag, soft/paved surface class. North is fixed up (`+z`); "orientation" therefore means
*which façade faces which cardinal aspect*, not a rotation of the grid. Site boundary = a
rectangular grid extent (the agent may set grid size = site). Movement is A\* octile; vertical
links are lift/stair portals; access is by tags.

---

## Rules

### SC-01 Take an inventory before you take a decision, and label every finding constraint or opportunity
- Rule: Produce a site inventory first (a factual list of what exists), then an analysis (what each fact does to the design), and tag every analysed item as `CONSTRAINT` (a fact that removes options: a boundary line, a slope class, a protected view, a noise source, an existing wall to keep) or `OPPORTUNITY` (a fact that adds value if used: an aspect, a view, a desire line, an existing opening, shade from an existing tree). No design parameter may appear that is not derived from a listed inventory item.
- Evidence: The UK national planning guidance states the method directly: "Well-designed new development responds positively to the features of the site itself and the surrounding context beyond the site boundary. It enhances positive qualities and improves negative ones" and lists the physical features to be inventoried — "the existing built development, including layout, form, scale, appearance, details, and materials; local heritage … and local character; landform, topography, geography and ground conditions; landscape character, waterways, drainage and flood risk, biodiversity and ecology; access, movement and accessibility; environment — including landscape and visual impact, microclimate, orientation, flood risk, noise, air and water quality; views inwards and outwards; the pattern of uses and activities" — and frames the analysis step as one "shaped by an understanding of the context that identifies opportunities for design as well as constraints upon it", sized "in proportion to the nature, size and sensitivity of the site and proposal" (National Design Guide, paras 41–43). Textbook site-analysis method is built on the same inventory→analysis→suitability sequence (LaGro, *Site Analysis*; Lynch with Hack, *Site Planning*).
- Source: Ministry of Housing, Communities & Local Government / DLUHC, *National Design Guide: planning practice guidance*, Jan 2021 — https://assets.publishing.service.gov.uk/media/602cef1d8fa8f5038595091b/National_design_guide.pdf — T1; James A. LaGro, *Site Analysis: A Class-Based Guide to Developing Site Planning and Design Skills*, Wiley (Open Library work record: 12 editions, first 2008, 2013 reprint) — T3; Kevin Lynch with Gary Hack, *Site Planning*, MIT Press (work record: 8 editions, first 1962) — T3.
- Class: DESIGN PRINCIPLE
- Scope: universal; the *depth* of the inventory is proportionate, not fixed
- Confidence: High
- Grid translation: Emit a site-fact table before the first plan: `factor | observed value | unit | tiles | class (CONSTRAINT|OPPORTUNITY) | rule ids it triggers`. Validation: (a) every parameter used later in the run (max footprint tiles, entrance tiles, aspect assignment, separation tiles) traces to a row; (b) every row has a class, or the run flags it as un-analysed; (c) report an `inventory_coverage` = analysed factors / the NDG factor list above (13 named factors), so silence about, say, drainage is visible rather than invisible.
- Exceptions / failure mode: Small, already-characterised infill sites where most factors are fixed by an inherited street wall — the inventory collapses to 4–6 rows; do not manufacture analysis to fill the table. Failure symptom: a plan whose only stated reason for a setback or an aspect is "looked better", or a factor discovered mid-run that retroactively invalidates the footprint (the classic case: the fire-access requirement found after the building is pushed to the boundary).

### SC-02 Register the boundary and the four aspect edges before placing a single tile
- Rule: A site is not "an area", it is a bounded parcel with four *edges* that are not equal. Before massing, record: boundary extent in tiles (`W × H`), which edge fronts which street / open space / rail / noise source, the access point(s) on each edge, and the cardinal aspect of each edge (N/E/S/W under `north = +z`). Any rule that mentions "orientation" or "setback" is evaluated per edge, never per site.
- Evidence: The federal accessibility standard defines a site in exactly edge terms: "Site — A parcel of land bounded by a property line or a designated portion of a public right-of-way" (2010 ADA Standards, glossary), and its route requirements are stated as connections *between site arrival points* (parking, public streets and sidewalks, each public transportation stop) and entrances — i.e. the boundary is where the requirements attach. The design guidance likewise treats the boundary as the datum for "relationship to the plot boundary — and whether they share party walls or not" (National Design Guide ¶24).
- Source: US Access Board, *2010 ADA Standards for Accessible Design* — https://www.access-board.gov/ada/ — T1; *National Design Guide*, Jan 2021 — https://assets.publishing.service.gov.uk/media/602cef1d8fa8f5038595091b/National_design_guide.pdf — T1.
- Class: DESIGN PRINCIPLE
- Scope: universal
- Confidence: High
- Grid translation: Emit `site = {w_tiles, h_tiles, area_tiles, area_m2 = area_tiles/4}` and four `edge = {aspect, frontage_tiles, front_of, noise_source(bool), access_tiles[], build_to_line_tiles}` records. Measurable checks that need this record and nothing else: `edge_access_covered` (does every edge with a frontage have ≥1 declared access tile set), `aspect_assigned` (all four edges have an aspect), and every later SC-03…SC-21 rule reads `edge` rather than the site. A 40×40-tile site = 1,600 tiles = 400 m² = 20 m × 20 m.
- Exceptions / failure mode: Interior/landlocked parcels with no street edge (access over a neighbour's land) still need an edge record — mark the edge `private_way` rather than dropping it. Failure symptom: an agent that treats the site as a square area and then discovers the service yard has no vehicle path, or that the only sunny aspect is already occupied by the noise edge.

### SC-03 Build the buildable envelope as a per-edge tile mask, not as an area subtraction
- Rule: Convert each edge's setback distance into whole tiles (round *inward*, i.e. down, so the envelope is never larger than allowed) and subtract to get a buildable rectangle; the building footprint must be inside that mask tile-for-tile. Never satisfy a setback by checking total permitted area — area checks pass plans that overrun one edge and underuse another.
- Evidence: Setbacks are defined per edge and as distances, not areas: "SETBACK — The distance from the street (in the case of a Front Setback) or property line to the nearest part of the applicable Building, Structure, measured perpendicular to the street or property line, in front of which no structure may be erected"; "SETBACK, FRONT — The minimum horizontal distance between any Building or Structure and the Front Lot Line"; rear and side the same way (Sanford, NC Unified Development Ordinance, Appendix A). Actual jurisdictional numbers, e.g. New York City residence districts: R1 — front yard 20 ft, side 8 ft; R2, R3-1, R3-2 — front 15 ft, side 5 ft; R3A, R4, R5 — front 10 ft, side 5 ft; R4B/R5B/R5D — front 5 ft, side 5 ft; R6–R12 — no front or side yard required (NYC Zoning Resolution Art. II Ch. 3, yard minimums §§23-32/23-33/23-34).
- Source: City of Sanford, NC, *Unified Development Ordinance*, Appendix A Definitions — https://www.sanfordnc.net/DocumentCenter/View/4980/Appendix-A---Definitions — T1; NYC Zoning Resolution, Article II Chapter 3 (Residential Bulk Regulations) — https://zr.planning.nyc.gov/article-ii/chapter-3 — T1.
- Class: CODE REQUIREMENT (jurisdiction-flagged: the footages are New York's; the *method* is transferable)
- Scope: universal method; every dimension jurisdiction-specific
- Confidence: High for the method and the definitions; Medium for the quoted NYC yard figures (read from the official zoning text as amended, but the district/suffix combinations are numerous — verify per district before use)
- Grid translation: `envelope_w = w_tiles - floor(front_setback/0.5) - floor(rear_setback/0.5)`, similarly for `h` (the ÷0.5 converts metres to tiles; `floor` is the inward rounding). Worked example on a 40×40-tile (20 × 20 m) site in an R4-equivalent district: front 10 ft = 3.05 m = 6.1 tiles → 6; rear 25 ft = 7.62 m = 15.2 tiles → 15; side 5 ft = 1.52 m = 3.05 tiles → 3 each side. Envelope = (40−6−15) × (40−3−3) = 19 × 34 = 646 tiles = 161.5 m² footprint ceiling. Emit that arithmetic, and a `setback_violation` check per façade tile (`distance_from_boundary_tile < required_tiles`). Flag any envelope smaller than the programme's minimum footprint as `SITE_TOO_SMALL` rather than silently encroaching.
- Exceptions / failure mode: Encroachments are almost always legal for some elements (canopy, steps, balconies, bay windows, driveways in the front yard, solar equipment) — NYC, for instance, allows wall articulation of ≤12 in (sub-tile, unrepresentable) and recesses ≤3 ft on ≤50 % of the aggregate street-wall width (ZR §23-431(d)). So an envelope breach is not automatically an error; it is an error *unless the element class is declared encroachable*. Failure symptom: an agent that lets the building overhang the front setback "because a canopy is allowed" and loses the whole frontage.

### SC-04 Apply FAR, site coverage and impervious coverage as three independent ceilings, in tiles
- Rule: Compute all three every time and report all three. Site coverage = footprint area ÷ site area (usually drawn at the roof outline). Floor area ratio = total floor area of all structures ÷ site area. Impervious coverage = built + paved surface ÷ site area. A plan can satisfy one and break another; a single-storey building with a car park can satisfy FAR and fail coverage or imperviousness, and a compact tower can satisfy coverage and fail a pedestrian-wind or amenity test.
- Evidence: Definitions from an adopted code: "LOT COVERAGE — The percentage of the area of a lot which is occupied by all buildings or other covered structures using the roof outline for all outer dimensions"; "FLOOR AREA RATIO (FAR) — The ratio of the gross floor area of all structures on a parcel to the gross area of the parcel on which such structures are located"; "IMPERVIOUS SURFACE — includes all buildings or structures measured at their greatest extent and so as to include areas overhung by eaves, balconies … also all paved or otherwise hard-surfaced areas such as buildings, pavement, gravel areas (e.g. roads, parking lots, paths), recreation facilities … and similar hard-surfaced areas" (Sanford UDO App. A). The measured scale of imperviousness by land use, and the ecological ceiling, come from watershed research: typical percent impervious cover — commercial/business district 85 %, industrial 72 %, townhouse (≤1/8-acre lots) 65 %, 1/4-acre lot 38 %, 1/3-acre 30 %, 1/2-acre 25 %, 1-acre 20 %, 2-acre 12 %; and "streams can show signs of degradation and can be considered stressed in watersheds where the impervious coverage exceeds 10–15 percent", with 100-year flood peaks potentially doubling above 20–30 % (University of Delaware NEMO, *The Implications of Impervious Cover*).
- Source: Sanford, NC, *Unified Development Ordinance*, Appendix A — https://www.sanfordnc.net/DocumentCenter/View/4980/Appendix-A---Definitions — T1; NEMO Program / University of Delaware, *Nonpoint Source Education Manual*, ch. 2 "Impervious Cover" — http://nemo.udel.edu/manual/chap2web.pdf — T2.
- Class: CODE REQUIREMENT (the coverage and FAR ceilings; the imperviousness bands cited with them are measured research values, not code)
- Scope: coverage and FAR are planning parameters — values are wholly jurisdictional and must be looked up; the imperviousness *thresholds* are hydrological, not legal, but apply only where runoff reaches watercourses
- Confidence: High for the three definitions and their independence; Medium for the 10–15 % stress threshold (a single research tradition, widely repeated); High for the per-land-use table as a sanity check on the agent's own arithmetic
- Grid translation: `coverage = footprint_tiles / site_tiles`; `FAR = Σ_floor_tiles / site_tiles` (each floor counted at its own extent, so a 40×40-tile site (1,600 tiles) with FAR 2.0 permits 3,200 floor tiles = 800 m² = e.g. two full floors, or four floors at half coverage); `impervious = (footprint + paved_tiles) / site_tiles`, where a `paved` classification must include driveways, parking, paths and roofs-as-projecting-features. Cross-check: any residential layout reporting impervious < 20 % or an office site reporting < 60 % is probably misclassifying paving as `walkable` ground. Report all three numbers with the tile counts that produced them.
- Exceptions / failure mode: FAR definitions differ in what they exclude — Sanford's FLOOR AREA excludes basements, interior balconies and mezzanines, elevator shafts and stairwells and enclosed porches, but *includes* accessory buildings. An agent using a different denominator will mis-price density by 10–20 %. Failure symptom: a "compliant" FAR computed on net room area while the jurisdiction measures gross external area (or the reverse), plus the tile-grid bias: because walls are one tile thick, a footprint measured *outer face* overstates a real wall-outline footprint slightly — state which convention you used.

### SC-05 Put the principal entrance where the traffic already is, and make it visible from the street
- Rule: The main entrance goes on the edge that carries the majority of arriving people, on the more important of the two frontages (at a corner, at the corner), faces the street rather than the car park, and is visible from the public way. Secondary entrances replicate this rule at their own arrival scale; they are not back doors.
- Evidence: A municipal design-review scorecard makes the two halves of this rule literally scoreable: "Building orientation at or near the street: parking or drive separates building from street = 0; at least 20 % of elevation within 5 feet of minimum setback = 1; at least 20 % of elevation is at minimum setback = 2" and "Building entrances visible from the street: no = 0; yes = 1" (City of Canby, OR, development criteria response, quoting code ch. 16). "Locate the main entrance door at the corner or on the more major street, on a corner lot" and "Secondary entrances from the parking should provide safe comfortable access, that does not require crossing of stacking lanes or driveways" (Toronto, *Urban Design Guidelines for Sites with Drive-Through Facilities*). National guidance requires "buildings facing the street to provide interest, overlooking and active frontages at ground level" and defines **Active frontage**: "The front of a building with openings onto the space that generate activity … [which] leads to people overlooking the space" (NDG ¶69, glossary).
- Source: City of Canby OR, *Project Meadowlark — Project Narrative and Criteria Response* (adopted-code criteria tables), 2024 — https://www.canbyoregon.gov/sites/default/files/fileattachments/planning_commission/meeting/packets/28404/attach_b_-_project_narrative_and_criteria_response.pdf — T1; City of Toronto, *Urban Design Guidelines for Sites with Drive-Through Facilities*, 29 Apr 2005 — https://www.toronto.ca/wp-content/uploads/2017/08/9491-Urban-Design-Guidelines-for-Sites-with-Drive-Through-Facilities.pdf — T1; *National Design Guide*, Jan 2021 — T1.
- Class: BUILDING-TYPE CONVENTION (strongest on street-facing commercial, civic and hospitality; the underlying reason generalises to all types)
- Scope: urban frontage sites; weak or irrelevant on campus, industrial or rural sites with no street
- Confidence: High
- Grid translation: Score the entrance plan the way Canby does: `frontage_contact = tiles_of_façade_within_5_tiles_of_build_to_line / frontage_tiles` (target ≥ 0.20 for the scored edge); `entrance_visible` = an entrance tile on the edge with the highest arrival weight, with ≥1 door tile and an unobstructed `walkable` sight corridor from the boundary tile in front (on this grid: the tile run between the door and the boundary must not be enclosed on both sides by blocked tiles for more than 4 tiles). On a corner site, place the door within 6 tiles of the corner. Report `entrance_edge`, `arrival_weight_by_edge`, and the Canby-style score so the choice is auditable.
- Exceptions / failure mode: Climate and security invert this in extreme cold, extreme heat or high-risk occupancies, where a sheltered vestibule off the main façade is correct — then keep the *legibility* (a marked, overlooked entrance) even when the *exposure* is avoided. Hostile-architecture and vehicle-ram-raising requirements can also push an entrance off a street frontage; note the reason explicitly rather than silently. Failure symptom: a "grand" entrance onto an internal drive with no pedestrian route to it, or a door that opens into the car park.

### SC-06 Keep vehicles and service movement off the public frontage
- Rule: Do not put parking, drive aisles or service yards between the building and the street. Service access belongs at the rear or flank, on the least valuable frontage, and must not force a pedestrian to cross a vehicle path to reach a door.
- Evidence: "Do not locate stacking lanes or driveways between the building and the street"; "where a setback is required by the Zoning By-law do not locate stacking lanes or driveways in the setback area between the building and the street"; "locate stacking lanes and driveways out of view of the public street and/or sidewalk, at the rear and/or flank of the building"; "provide vehicular site access from the side or less major street where possible, to improve pedestrian safety on the major street sidewalk"; "do not locate parking or vehicular site exits or entrances between the building and the street"; "provide parking adjacent to the secondary entrance doors … such that it is not necessary for pedestrians who arrive by car to cross driveways or stacking lanes to enter the interior of the building" (Toronto, drive-through guidelines, §6.1.3–6.1.4). The scoring in Canby ch. 16 penalises exactly the opposite ("parking or drive separates building from street = 0"). The federal standard supplies the vocabulary: "Service Entrance — An entrance intended primarily for delivery of goods or services" (2010 ADA Standards, glossary).
- Source: City of Toronto, *Urban Design Guidelines for Sites with Drive-Through Facilities*, 2005 — https://www.toronto.ca/wp-content/uploads/2017/08/9491-Urban-Design-Guidelines-for-Sites-with-Drive-Through-Facilities.pdf — T1; City of Canby OR criteria response — T1; US Access Board, 2010 ADA Standards — https://www.access-board.gov/ada/ — T1.
- Class: DESIGN PRINCIPLE (becomes enforceable where the frontage setback is itself legally protected)
- Scope: urban and suburban frontage sites with any vehicle function
- Confidence: High
- Grid translation: Define `frontage_zone` = tiles between the build-to line and the façade on each street-facing edge, and validate `no_vehicle_tile_in_frontage_zone` (a `paved/walkable` tile classified as drive aisle, parking or service must not lie inside it). Validate `ped_crossing_count` on every pedestrian edge-to-door path: an A\* route from the street boundary tile to a door tile should cross 0 vehicle-classified tiles; if it must cross, the layout fails and the service move goes to the flank. Tag the service edge and keep it off the aspect reserved for amenable rooms (SC-13).
- Exceptions / failure mode: Deep-block sites with no rear or flank access, and drive-through/retail-park typologies, where the vehicle forecourt *is* the site. Then manage it — the same Toronto guidance's remedy is to keep the pedestrian route continuous and the stacking out of the public sightline, not to abandon the rule. Also: fire access (SC-09) can require a road where the design wants a plaza; fire access wins. Failure symptom: a forecourt that consumes the only sunny aspect, or a pedestrian route whose shortest path is across a loading lane.

### SC-07 Minimise the number and width of curb cuts, and space them by the road's functional class
- Rule: Fewer, narrower vehicle accesses perform better than many. Access spacing and the offset between opposing accesses are set by the classification and speed of the road the site joins, not by convenience. On a corner site, keep the turning corner tight so pedestrians are not forced into a long crossing.
- Evidence: "Minimize the number and width of curb cuts; provide only one curb cut for a mid-block site and a maximum of two curb cuts, if necessary, for a corner site … provide the minimum width of curb cuts required by the City of Toronto Access Management Guidelines" (Toronto, §6.1.4). Published numeric spacing standards, measured centre-of-access to centre-of-access (Orem, UT, Access Management Standards, Tables 1–2): unsignalised full-movement access — major/principal arterial 660 ft, minor arterial 500 ft, collector 500 ft, commercial local 660 ft, residential local 125 ft, residential sub-local 100 ft; right-in/right-out only — 330 / 250 / 250 / 330 / 100 / 75 ft; minimum offset between driveways on opposite sides of an undivided roadway — major arterial 600 ft at 85th-percentile speeds ≥45 mph (300 ft below), minor arterial 220 ft, collector 200 ft, commercial local 200 ft. On the corner itself: "It is better to design the junction on this basis [buildings and footways defining the space] rather than purely on vehicle movement … a wide carriageway with tight, enclosed corners makes a better junction than cutback corners with a sweeping curve. This might involve bringing buildings forward to the corner" and, on kerb radius, "Small radius (eg. 1 metre): pedestrian desire line is maintained; vehicles turn slowly (10 mph – 15 mph) … Large radius (eg. 7 metres): pedestrian desire line deflected; vehicles turn faster (20 mph – 30 mph)" (Manual for Streets, §5.5 and Fig. 6.2).
- Source: Orem City, UT, *Transportation Master Plan — Appendix B: Access Management Standards* — https://orem.gov/wp-content/uploads/2024/12/TMP-Appendix-B.pdf — T1; City of Toronto drive-through guidelines, 2005 — T1; DfT/DETR, *Manual for Streets*, 2007 — https://assets.publishing.service.gov.uk/media/5a7e0035ed915d74e6223743/pdfmanforstreets.pdf — T1.
- Class: CODE REQUIREMENT (the published spacing and offset tables; jurisdiction-flagged — the 'fewer cuts, tighter corners' reasoning transfers even where the numbers do not)
- Scope: sites with direct access to a classified road
- Confidence: High for the transferable rule and the mechanism; High for the numbers *as published by those authorities*; Low for their transfer to any other jurisdiction
- Grid translation: Store `road_class` and `speed` as edge attributes. Permitted access count: 1 on a mid-block frontage, ≤2 on a corner. Convert spacing to tiles (metres × 2): 660 ft = 201.2 m = 402 tiles; 500 ft = 152.4 m = 305 tiles; 250 ft = 76.2 m = 152 tiles; 125 ft = 38.1 m = 76 tiles; the opposing-side offset of 220 ft = 67.1 m = 134 tiles. Note the consequence: a 40-tile site frontage cannot satisfy an arterial spacing standard at all, and that arithmetic *is* the finding — on an arterial frontage, take access from a side street or an alley. Kerb/corner radius: use 2 tiles (1 m) where the desire line must be held, 14 tiles (7 m) only if vehicle speed is accepted — record the choice as an explicit trade. Sight-line check per access: within `X = 5 tiles` (2.4 m) of the access centreline back along the minor arm and `Y = SSD tiles` (Manual for Streets Table 7.1: 20 mph/32 km/h → 22 m = 44 tiles; 30 mph/48 km/h → 40 m = 80 tiles) along the major arm, no `blocked` tile may intrude.
- Exceptions / failure mode: Shared or right-turn-restricted accesses, frontage roads, and median-raided arterial frontages change the numbers; and existing non-compliant accesses are usually grandfathered (Orem records that "some existing signals do not comply with spacing requirements"). Failure symptom: three closely spaced cuts on an arterial frontage, or a "generous" 7 m corner radius that raises turning speed and kills the crossing.

### SC-08 Give waiting and transferring vehicles their own sized room, off the frontage
- Rule: Any use that generates queuing vehicles (drive-through, take-away, bank/pharmacy window, ride drop-off) or goods transfer (loading, refuse, delivery) must provide that room at its own published dimension, at the rear or flank, screened from the street, and shaped so one queue cannot block another movement.
- Evidence: "Provide a minimum of 10 stacking spaces on site for restaurant and food sale use drive-through facilities"; "a minimum of 4 stacking spaces … for banking, pharmacies and similar non-food related use drive-through facilities"; "provide stacking spaces which are 3.5 meters in width and 6.5 meters in length"; "multiple windows servicing a single stacking lane … should be considered to promote reduced idling"; "multiple stacking lanes for a single user are discouraged" (Toronto, §6.1.3). Loading: required berths by floor area — under 5,000 sf = 0, 5,000–25,000 = 1, 25,000–60,000 = 2, 60,000 and over = 3; berth sizes "Commercial uses — 13' x 35'; Industrial uses — 12' x 60'"; "Berths shall have an unobstructed minimum height of 14'"; "Required loading areas shall be screened from public view, from public streets, and adjacent properties" (Canby, OR Development Code §16.10.060 as applied in the Project Meadowlark criteria response).
- Source: City of Toronto drive-through guidelines, 2005 — T1; City of Canby OR criteria response (code §16.10.060), 2024 — T1.
- Class: CODE REQUIREMENT (jurisdiction-flagged: the berth counts and stacking minima are Canby's and Toronto's, and the food/bank/pharmacy split is a type convention inside that code)
- Scope: food service, banks/pharmacies, warehouses, hotels with banqueting, supermarkets, hospitals, any type with goods transfer
- Confidence: High as published by those authorities; Medium for transfer to other US/CA municipalities; Low outside North America where berth sizes differ
- Grid translation: A stacking space 3.5 × 6.5 m = 7 × 13 tiles = 91 tiles (22.75 m²); 10 spaces ≈ 910 tiles plus aisle — on a 1,600-tile (400 m²) site, a drive-through is arithmetically impossible; report `stacking_feasibility = false` rather than drawing a compressed lane. A commercial berth 13 × 35 ft = 3.96 × 10.67 m = 8 × 22 tiles (176 tiles); an industrial berth 12 × 60 ft = 3.66 × 18.29 m = 8 × 37 tiles (296 tiles). Truck court area ≈ 2.5 × berth area to allow the manoeuvre (derived from SC-09 turning radii, not a published figure — `UNCITED — heuristic`). Validate: no `queue` or `berth` tile in the frontage zone (SC-06), no queue tile sharing a wall with a bedroom/quiet room, and each queue physically continuous from its window to its exit.
- Exceptions / failure mode: Urban sites served by an alley or a rear loading court share one facility between tenants — that is better, not a breach, provided the shared lane has capacity for the peak coincidence (Toronto: "the number of required stacking spaces may change as a result of studies required as part of the approvals process"). The 14 ft (4.27 m ≈ 8.5-tile) unobstructed height is unrepresentable on a plan-only grid; carry it as a clearance *tag* on the lane, not as a drawing. Failure symptom: a drive-through lane whose queue wraps into the parking aisle, or a dock sized for a van in front of a truck berth.

### SC-09 Keep an apparatus route within reach of every ground-floor wall, and design the turnaround before the dead end runs out
- Rule: A fire apparatus access road must reach within a published distance of all parts of the facility and of all parts of the first-storey exterior wall. Dead-end lengths, widths (with parking accounted for), turning radii, surface, gradient and gate locking are all specified and must be satisfied by the site layout, not promised at approval.
- Evidence: "Fire Apparatus shall have access to within 150 feet of all portions of a facility and all portions of the exterior walls of the first story of the building as measured by an approved route around the exterior of a facility or building"; unobstructed width, exclusive of shoulders: 20 ft with no parking, 26 ft with parallel parking on one side, 32 ft with parking both sides (26 ft where a hydrant sits on the road, and for dead-ends over 501 ft); turning radius "35 foot minimum inside turning radius, 55 foot minimum outside turning radius"; "Dead-end fire apparatus access roads in excess of 150 feet shall be provided with width and turnaround provisions in accordance with International Fire Code Table D103.4 & D103.1" (0–150 ft none required; 151–500 ft turnaround required; 501–750 ft required at 26/32/38 ft; over 750 ft special approval); surface "capable of supporting the imposed load of fire apparatus weighing at least 75,000 pounds"; "unobstructed vertical clearance of not less than 13 feet 6 inches"; grade ≤10 % longitudinally, cross slope ≤5 %, and ≤5 % change along any 10 ft section (Great Falls, MT Fire Marshal, *Fire Lanes / Fire Apparatus Access Roads*, 05.10.23).
- Source: City of Great Falls, MT Fire Marshal's Office, *Fire Lanes / Fire Apparatus Access Roads* (IFC Appendix D restated), 2023 — https://www.greatfallsmt.gov/DocumentCenter/View/950/Fire-Apparatus-Access — T1.
- Class: CODE REQUIREMENT (jurisdiction-flagged: this is one city's restatement of IFC Appendix D; confirm the adopted edition)
- Scope: all non-detached-house construction; the two-house exception is itself in the text
- Confidence: High as published; Medium for exact transfer (IFC editions vary — e.g. the 150-ft reach and the 40-ft width variants differ by edition and by local amendment)
- Grid translation: In tiles (round a *maximum* distance down, a *minimum* width/radius up): reach 150 ft = 45.7 m → **≤91 tiles** of A\* route to any first-storey wall tile; width 20 ft = 12.2 tiles → **13**, 26 ft = 16 tiles, 32 ft = 20 tiles, 38 ft = 24 tiles; turning radius 35 ft inside → 22 tiles, 55 ft outside → 34 tiles; dead-end bands 151–500 ft = 92–305 tiles (turnaround required), 501–750 ft = 306–457 tiles (and 24-tile minimum width), over 750 ft = special approval; 75,000 lb capacity and 13 ft 6 in (8.2-tile) clearance are attributes to *tag*, not to draw. Measurable checks: (a) every first-floor `blocked` wall tile is within 91 A\*-steps of a tile classified `fire_apparatus_way`; (b) any `fire_way` dead end is ≤91 tiles or has a declared turnaround geometry; (c) `blocked` and `door` tiles do not intrude into the 13/16/20-tile clear width; (d) gates carry a `fire_approved_lock` tag.
- Exceptions / failure mode: The published exception is narrow — for not more than two Group R-3 (single-family) or Group U occupancies served by a private access, with a sprinklered building and where an access road "cannot be installed because of location of property, topography, waterways, nonnegotiable grades", the fire code official may extend the 150-ft dimension. Do not generalise it. Also note the direct conflict with SC-06/SC-21: a fire road wants width along the façade, a plaza wants the same tiles. Failure symptom: a courtyard plan with no through-route for an appliance, or a "fire lane" that is 10 tiles wide because the parking on both sides was counted.

### SC-10 Lay the pedestrian network on desire lines and judge the site by walk-time to transit
- Rule: Before drawing any path, compute the straight octile lines between the site's real origin/destination pairs (street corners, transit stop, parking, entrances) and let the route grid follow them; provide crossings where the desire line meets the road. Then measure the site's transit proximity as an actual walkable-path distance, not as the crow-flies radius.
- Evidence: "Pedestrian routes need to be direct and match desire lines as closely as possible. Permeable networks help minimise walking distances"; crossings "should be matched to the pedestrian desire lines. If the crossing pattern is fairly random and there is an appreciable amount of pedestrian activity, a minimum frequency of 100 m is recommended" (Manual for Streets §6.3.6, §6.3.8; the 100 m figure is attributed there to *Inclusive Mobility*, DfT 2005). Empirically, transit use is measured against proximity buffers: the land-use/travel literature surveyed by Ewing & Cervero repeatedly defines accessibility as activity "within one-quarter mile" of a bus stop and one-half to one mile around rail stations, and concludes that grid-like networks "improve walk and transit access by offering relatively direct routes and alternatives to travel along high-volume, high-speed roads" (Ewing & Cervero, *Travel and the Built Environment: A Synthesis*, tables A-2/A-4 and Transportation Networks section).
- Source: DfT/DETR, *Manual for Streets*, 2007 — T1; Reid Ewing & Robert Cervero, "Travel and the Built Environment — Synthesis", *Journal of the American Planning Association* 76(3), 2010 (full text as filed in the City of Santa Clarita Draft EIR, Appendix 4.3i) — https://filecenter.santa-clarita.com/Planning/VistaCanyon/DraftEIR/Volume3/Apx_4_3i_Travel_Built_Environment.pdf — T2.
- Class: DESIGN PRINCIPLE
- Scope: universal in urban/suburban sites; weak on rural or auto-served sites
- Confidence: High
- Grid translation: For each OD pair with trips above the programme's threshold, compute the octile straight line (`max(dx,dz) + 0.41421·min(dx,dz)`) and mark crossed tiles as `desire`. Checks: `desire_coverage = Σ trips whose desire line lies inside a declared route / Σ trips` ≥ 0.7; crossing spacing along a road-crossing frontage ≤ 200 tiles (100 m); `walk_tiles_to_stop = A* distance from the main entrance door tile to the declared stop tile` with 400 m = 800 tiles (bus) and 800 m = 1,600 tiles (rail) as the assessment bands, reported as `directness_ratio = straight_octile / walked_path` (target ≥ 0.8; below that the network, not the site, is the problem).
- Exceptions / failure mode: Desire lines describe what people *want*, not what is safe or legal — they ignore traffic, level changes, security and privacy gradients. Manual for Streets explicitly prefers surface crossings over footbridges and subways "unless local topography or other conditions make them necessary". Failure symptom: a beautifully straight route across a five-lane arm, or a route that crosses the service yard to save 30 tiles.

### SC-11 The inherited street grain is a constraint: block length and connectivity set what the site can be
- Rule: Read the existing block dimensions, junction frequency and network type around the site before proposing a site layout, and keep the new routes continuous with that grain. A large parcel is a strong argument for subdividing it with new streets, not for a single superblock with one access.
- Evidence: "CONDITION 2: Most blocks must be short; that is, streets and opportunities to turn corners must be frequent", argued from the 800-foot Manhattan block whose residents "may very well never enter the adjacent blocks on Eighty-seventh Street and Eighty-ninth Street for years", and concluding "frequent streets and short blocks are valuable because of the fabric of intricate cross-use that they permit among the users of a city neighborhood. Frequent streets are not an end in themselves. They are a means toward an end" (Jane Jacobs, *The Death and Life of Great American Cities*, ch. 9 "The need for small blocks", pp. 178–193). Empirical support: non-work VMT related to "the proportion of four-way intersections within neighborhoods and to the proportion of blocks with quadrilateral shapes" (Cervero & Kockelman 1997, as reported in Ewing & Cervero), and the direct comparison "Savannah, Georgia's fine-meshed grid of 200-foot block faces is pedestrian-friendly. Phoenix, Arizona's one-mile grid of four-lane arterials is not."
- Source: Jane Jacobs, *The Death and Life of Great American Cities*, Random House, 1961 (full text mirror: https://www.petkovstudio.com/bg/wp-content/uploads/2017/03/The-Death-and-Life-of-Great-American-Cities_Jane-Jacobs-Complete-book.pdf) — T3; Ewing & Cervero 2010 (Santa Clarita EIR copy) — T2.
- Class: DESIGN PRINCIPLE
- Scope: urban sites and multi-parcel masterplanned sites; not applicable to a single isolated building on a large rural parcel
- Confidence: Medium-high for the movement/connectivity effect (measured, correlational, mixed sign across studies), High for the design argument as stated
- Grid translation: Record `context_block_length_tiles` and `junction_frequency` from the surrounding grid; then require the new site's internal route spacing to sit within a band of it (e.g. within ±50 %) unless a documented reason exists. If `site_frontage_tiles / context_block_length_tiles > 2`, propose subdivision streets rather than one long perimeter. Measurable: `through_routes` = number of declared routes crossing the site boundary twice; `site_internal_directness` = octile distance across site ÷ A\* distance using the declared route grid (target 1.0–1.25).
- Exceptions / failure mode: Very high-speed or high-volume barrier roads, rail corridors, and topography make a fine grain unsafe or impossible; hospitals, prisons, campuses and industrial sites *want* low permeability for control. Jacobs's own caveat applies — short blocks do nothing "if that end … is thwarted by too repressive zoning". Failure symptom: a 600-tile-deep interior block with one curb cut, or a residential "grid" whose every street terminates at a security gate.

### SC-12 Face the ground floor to the street; a long blank perimeter is a liability on both sides of it
- Rule: Wherever the site adjoins a public or shared space, the building must present openings, activity and overlook along it. A large single-use element with a low internal intensity and a long perimeter is the specific thing to avoid, because it kills the life of its own edge and its neighbours'.
- Evidence: The urban diagnosis is quantified: "Still other borders have scant use along them because the massive single elements that form them possess such a low intensity of land use, relative to the great perimeters they possess … Thirty workers to an acre is so low-intensity a use of city land, and 100 acres affords such an immense perimeter, that this enterprise will create scant use all along its borders. From whichever cause the effect is produced, the pertinent effect is scant use (few users, there in the flesh) along a large-scale or stretched-out perimeter" (Jacobs, ch. 14 "The curse of border vacuums", pp. 257–271). The design requirement: "successful streets characterised by buildings facing the street to provide interest, overlooking and active frontages at ground level", "relationship between building fronts and backs" (NDG ¶69), and communal spaces that "be positioned to allow overlooking" (London Plan 2021, ch. 3 design requirements for housing).
- Source: Jane Jacobs 1961 — T3; *National Design Guide*, Jan 2021 — T1; *The London Plan* (GLA, 2021) ch. 3 — https://www.london.gov.uk/sites/default/files/the_london_plan_2021.pdf — T1.
- Class: DESIGN PRINCIPLE
- Scope: urban and suburban sites, and any campus with internal streets
- Confidence: High for the design requirement; Medium for the behavioural claim (eyes-on-the-street/insecurity effects are contested on causation)
- Grid translation: Compute the **edge intensity** the way Jacobs does: `users_per_boundary_tile` (or floor-area-per-boundary-tile, or doors-per-boundary-tile) for each edge; flag any edge whose value falls below the site mean by more than a factor of 3 as a `border_vacuum_risk`. Checks: `frontage_openness = door_or_glazed_tiles / façade_tiles_on_public_edge` (declare a target per type); `blank_run_max_tiles` = longest unbroken run of `blocked` tiles with no opening on a public edge (recommend a hard cap, e.g. 24 tiles = 12 m); `overlook_cover` = share of public open-space tiles visible from ≥1 occupied tile of the building (line-of-sight over `blocked` tiles on the same floor).
- Exceptions / failure mode: Genuinely hostile edges (a freeway, a rail line, a hazardous yard) should *not* be activated; there the correct answer is a buffer, not a frontage, and the same is true of high-security and back-of-house edges. Failure symptom: a "lobby" onto a service yard, or an amenity terrace whose only oversight is a car park.

### SC-13 Assign the four aspects before designing the plan, and let daylight, noise, view and wind each claim a different façade
- Rule: Decide, per façade, which aspect it faces and what it is for — which rooms want sun, which must be shielded, which holds the entrance, which holds services — and lock that assignment before the internal plan. Aspect assignment is the single cheapest site decision and the hardest to recover from later.
- Evidence: National guidance lists orientation, microclimate, noise, views "inwards and outwards", and sun among the inventory items that must shape siting (NDG ¶43), and the sunlight-impact literature shows the effect is directional: "buildings on the south east, south or south west side of dwellings potentially having the greatest effect on sunlight" (Barnsley SPD §3.6); BRE guidance tests sunlight specifically on windows facing "within 20° of due south". For tall buildings the site decision is explicitly about aspect: "locate and orient buildings, parks, and open space to maximize sunlight access, sky view, and energy efficiency" (Toronto, *Tall Building Design Guidelines*, §1.2 rationale).
- Source: *National Design Guide* Jan 2021 — T1; Barnsley MBC, *Residential Amenity and the Siting of Buildings* SPD — https://www.barnsley.gov.uk/media/15718/residential-amenity-and-the-siting-of-buildings-spd.pdf — T1; BRE, *Site Layout Planning for Daylight and Sunlight: A Guide to Good Practice*, 3rd ed. 2022 (copy adopted on South Dublin CC) — https://www.sdcc.ie/en/devplan2022/adopted-plan/related-documents/site-layout-planning-for-daylight-and-sunlight-a-guide-to-good-practice.pdf — T2; City of Toronto, *Tall Building Design Guidelines*, May 2013 — https://www.toronto.ca/wp-content/uploads/2018/01/96ea-cityplanning-tall-buildings-may2013-final-AODA.pdf — T1.
- Class: DESIGN PRINCIPLE
- Scope: universal for occupancies with human occupancy; strongest for residential, education, healthcare, hospitality
- Confidence: High for the method; High for the sun-path facts (geometry); Medium for the claim that a specific aspect is best in an unspecified climate
- Grid translation: Emit `aspect_assignment = {N_edge: use, E_edge: use, S_edge: use, W_edge: use}` with a reason per edge, derived from SC-02's edge records. Then validate the plan against it: `quiet_faces_used = room_tiles_of_declared_quiet_type / Σ room_tiles on edges tagged non-noise`; `served_faces` = share of programme space on the assigned service edge; and an aspect-reversal flag when a bedroom abuts the noise edge or a plant room abuts the entrance edge. Because there is no section, express "sun" as *aspect + no-shading-neighbour-tag*, and derive the winter-sun test only where a protected space exists (SC-16).
- Exceptions / failure mode: Deep-plan types (department stores, museums, distribution warehouses, data halls) have no per-room daylight claim, and in hot-arid climates the sunny aspect is the one to *shade*, not the one to occupy. Failure symptom: an agent that optimises the internal adjacency graph and produces a plan with 40 % of habitable rooms on the service/noise edge.

### SC-14 Use the noise-source edge tag to decide what the building shows the source, and what it hides
- Rule: Where a road, rail, plant, airport or industrial neighbour makes an edge noisy, put the building's tough side there — circulation, services, structure, buffered or unoccupied rooms, or the massing itself as a screen — and turn the quiet side out. Attenuation is a site-layout decision before it is a façade decision.
- Evidence: The federal land-use/noise compatibility matrix states the outcome per use rather than per wall: below DNL 65 all land uses are "compatible without restrictions"; residential is "not compatible and should be prohibited" above 65; schools, hospitals and nursing homes require a noise-level reduction (NLR) of 25 dB in the 65–70 band and 30 dB in 70–75 and are incompatible at 75 and above; offices need NLR 25 at 70–75, NLR 30 at 75–80, and are incompatible at 80–85; parking and transportation land uses remain compatible up to the 80–85 band (Table reproduced from 14 CFR Part 150 in the Charlotte Douglas International Airport Part 150 Study Update, Appendix A, Aug 2024). The DNL 65 threshold exists because, on the Schultz curve, that is "the cumulative noise exposure level above which residential land uses are not compatible without [sound insulation]". The Part 150 text itself allows local adjustment: "Adjustments or modifications of the descriptions of the land-use categories may be desirable after consideration of specific local conditions."
- Source: *Charlotte Douglas International Airport 14 CFR Part 150 Study Update — Appendix A, Applicable Laws, Regulations and Policies* (reproducing 14 CFR §150.151 land-use compatibility guidelines), Aug 2024 — https://cltpart150.com/wp-content/uploads/2024/08/06-DRAFT-CLT-Part-150-Study-Update-Appendix-A-Applicable-Laws-Regulations-and-Policies.pdf — T1.
- Class: STANDARD (US federal land-use/noise compatibility criteria, aviation-specific; the siting response is drawn from them)
- Scope: sites adjoining a measurable noise source; the numeric matrix is US aviation land-use compatibility, not a road-noise code
- Confidence: High as published; Low for direct transfer of the DNL bands to road/rail noise
- Grid translation: Tag the offending edge `noise_source = {type, level_band, aspect_from}`; tag room types with `noise_sensitivity ∈ {high (sleep, quiet, teaching, care), medium, low (plant, store, circulation, garage)}` and validate `no_high_sensitivity_room_tiles_on_noise_edge` unless a declared attenuation measure exists. Use massing as the screen: place the tall/long element between the source and the open space, so the `protected_tiles` set (the amenity court) is downwind-and-shielded; report `screen_effectiveness` = share of open-space tiles whose straight line to the noise edge crosses ≥1 building tile. Interior levels (the 25/30 dB NLR column) are a façade property this grid cannot draw — carry them as a per-room tag so the plan records "this room needs NLR 30".
- Exceptions / failure mode: Screening with a mass also blocks ventilation, daylight and escape routes, and a noise screen placed *for* the resident may be placed *against* the neighbour (a bar that shadows the neighbouring garden, SC-16/17). Also, low-frequency noise (rail joints, plant) is not stopped by a plan manoeuvre. Failure symptom: a courtyard plan that is quiet, dark and unventilated, or a "shield" building that dumps its noise on the school next door.

### SC-15 Separate facing façades by the jurisdiction's privacy and daylight distance, and take the greater of the two
- Rule: The distance between facing habitable-room windows is not a taste question; published separation minima exist for privacy/outlook and for daylight, and the governing value is whichever is greater once the obstruction's size and storey count are taken into account.
- Evidence: "Any building at single or two storey height should be a minimum 25 m from the windows of any habitable rooms in any nearby dwelling … Any building at 3 storey height should be a minimum 30 m from the windows of any habitable room … The larger the building footprint the greater the distance … a building more than 20 m long or wide behind or in front of the main windows to the habitable rooms of a dwelling should be a minimum 35 m away … Any building higher than 3 storeys will need careful assessment"; relaxations are allowed where site levels, screening or the town-centre context justify them, and developments "designed to control aspect or which employ screening may allow closer spacing" (Barnsley MBC SPD §3.7). On the daylight side the tests are angular, not linear: sufficient daylight to an existing dwelling is "achieved where an unobstructed vertical angle of 25 degrees can be drawn from the centre point of the lowest window, the 25 degree rule"; and BRE's modern test is a vertical sky component of 27 % — above which "conventional window design will [suffice]", between 15 % and 27 % (obstruction angle 25°–45°) "special [window] designs" are needed, and for an *existing* window a VSC below 27 % and below 0.80× its former value means "occupants of the existing building will notice the reduction" (Barnsley §3.4; BRE 3rd ed. §§2.1, 2.2.7).
- Source: Barnsley MBC, *Residential Amenity and the Siting of Buildings* SPD — T1; BRE, *Site Layout Planning for Daylight and Sunlight*, 3rd ed. 2022 (SDCC-hosted copy) — T2/T3.
- Class: STANDARD (UK planning guidance; jurisdiction-flagged — the separations are Barnsley's and BRE's, the 'take the greater of the two tests' method transfers)
- Scope: residential and any occupancy with habitable rooms near a boundary; the 25/30/35 m figures are UK
- Confidence: Medium-high (guidance, explicitly non-mandatory in its own words, but it is what decisions are actually tested against); High for the method of taking the governing of two tests
- Grid translation: `25 m = 50 tiles`, `30 m = 60 tiles`, `35 m = 70 tiles`, `20 m length trigger = 40 tiles`. Emit `facing_pair` records for every pair of `habitable` window tiles on opposite façades across a gap (own site or neighbour tag), compute `gap_tiles` and check against the storey-banded minimum; also compute the daylight proxy `vertical_angle = atan(h / gap)` per tile — since the grid has no heights, require the agent to carry `assumed_storey_height` (BRE/typical practice aside, use the jurisdiction's own figure where published) and report the resulting angle in degrees with the 25°/45° breakpoints. Where both tests apply, `governing_distance = max(privacy_min_tiles, daylight_min_tiles)`. Note that a single 0.5-m tile cannot resolve 25° at typical distances — round the *distance up*.
- Exceptions / failure mode: The same document warns of the conflict: "Under certain circumstances, the Building Regulations control the number and size of windows and door openings (unprotected areas) fronting a boundary in order to minimise the risk of fire spread over the relevant boundary, this may be in conflict with any planning requirements." So closeness wanted for fire (fewer/larger openings) fights closeness allowed by privacy. Failure symptom: a "courtyard" plan whose amenity faces are 30 tiles apart and permanently dark, or an agent that satisfies the distance for its own rooms and shadows the neighbour's.

### SC-16 Test overshadowing against the specific protected thing next door, using the jurisdiction's own sun rule
- Rule: Overshadowing is only a constraint where a rule, a right, or a valued use exists on the receiving side. Identify the protected receivers (public open space, a particular window, a garden, a street frontage), identify the jurisdiction's sun rule (a date, a time window, an hours total, or a plane), and check the massing against it before finalising height and footprint.
- Evidence: A planning authority's mechanism, stated precisely: "A Sun Access Plane is a geometric, three dimensional, planar surface that is set at the same angle as the sun at a specific date and time and sets the upper building height"; "No Additional Overshadowing controls protect the existing sunlight to Public Places that are already surrounded by tall development … preserve sunlight that passes through gaps between buildings and around buildings to reach public spaces"; "The dates used to generate these controls are set at the most conservative sun angles, which ensures protection throughout the remainder of the year when the sun is higher in the sky" — with Table 5.7 setting, per place, the intended protection period and date: the Royal Botanic Gardens and the Domain, "9am–2pm, all year", primary plane date 21 June; Wynyard and Lang Park, "12–2pm"; Hyde, Belmore, Prince Alfred and Harmony Parks, "10am–2pm"; Macquarie Place and Martin Place, 14 April plane dates (City of Sydney DCP 2012 §5.1.7). Tall-building guidance sets the street test: limit the base-building scale "while maintaining access to at least 5 hours of sunlight on the opposite side of the street at the equinoxes", and requires Sun/Shadow studies that "focus on the equinoxes — March 21 and September 21" (Toronto Tall Building Design Guidelines §1.4). For amenity space, BRE's criterion: "a garden or amenity area should receive at least two hours of sunlight on 21 March. If as a result of development the area that can receive two hours of direct sunlight on 21 March is reduced to less than 0.80 times its former value, then the loss of sunlight is [noteworthy]" (BRE 3rd ed. §3.3). Right-to-light is a *separate, private* mechanism: an easement acquired by 20 years' enjoyment, whose adequacy is judged by the classic test in *Colls v Home and Colonial Stores Ltd* [1904] AC 179 in terms of what is sufficient for "the ordinary purposes of inhabitancy [and business]" (Law Commission, *Rights to Light*, Law Com No 356, 2014).
- Source: City of Sydney, *Development Control Plan 2012 — Section 5 Specific Areas* (Sun protection of public parks and places, Table 5.7) — https://www.cityofsydney.nsw.gov.au/-/media/corporate/files/publications/development-control-plans/2024/section5-dcp2012_030524.pdf — T1; City of Toronto, *Tall Building Design Guidelines*, May 2013 — T1; BRE 3rd ed. 2022 — T2/T3; Law Commission of England & Wales, *Rights to Light*, Law Com No 356 / HC 796, 2014 — https://assets.publishing.service.gov.uk/media/5a7dac39ed915d2acb6ed74c/44872_HC_796_Law_Commission_356_WEB.pdf — T1.
- Class: CODE REQUIREMENT (jurisdiction-flagged; both planning sun access and private right to light)
- Scope: dense urban sites with protected open space, neighbouring habitable windows, or an existing right; irrelevant on open sites
- Confidence: High for the mechanisms and the cited thresholds as published; Low for cross-jurisdiction transfer — right-to-light exists in England/Wales and a handful of other systems and not in most US codes
- Grid translation: Add a `protected_receiver` attribute to relevant tiles outside the boundary: `{type: park_window_garden_street, rule: {date, time_window, hours}}`. Because the grid has no section, carry height as a site attribute (storey count × declared floor height) and compute the shadow length arithmetically: `shadow_reach_tiles = H_m / tan(sun_altitude_deg) × 2`, cast along the reciprocal of the sun's azimuth (north-up: a south sun casts north). Report, per receiver: hours lost, area of the 2-hour contour lost versus the 0.80× test, and whether any receiver tile is breached. For Sun-Access-Plane-style controls, convert to a **height cap per distance from the protected space** and apply it as a second envelope mask alongside SC-03's setback mask — the smaller envelope governs.
- Exceptions / failure mode: The receiving site may itself change (a vacant lot becomes a school), which is why "no additional overshadowing" exists; and a plane drawn on the worst sun day is very conservative on every other day. Also, an agent with an assumed uniform storey height will get the shadow wrong for stepped massing. Failure symptom: a plan with a legal height that shades a protected park, or the reverse: refusing a legal massing because a generic 45° rule-of-thumb was used instead of the jurisdiction's actual rule.

### SC-17 Read topography as a slope-class buildability mask plus an accessible-route budget
- Rule: Classify the site by slope percentage bands, mark the unbuildable or protected bands, then place footprint, roads and accesses in the buildable bands — and separately check that every required pedestrian route satisfies the maximum slope for an accessible walking surface, converting slope into route length.
- Evidence: A hillside ordinance's operative numbers: the chapter applies to "limits that contain slopes equal to or greater than fifteen percent. No development shall occur on slopes equal or greater than fifteen percent except as specifically allowed"; the required slope survey classifies the site "in increments of 0–14.99 percent, 15–29.99 percent, and 30 percent or [greater]", must "identify and delineate all disturbed and undisturbed areas" and "limits of disturbance and buildable areas", and requires both pre- and post-development slope-district maps; "Contiguous slopes of 30 percent or greater are to be protected" from disturbance, with narrow exceptions where the area is isolated and its removal will not create unstable geologic conditions (Saratoga Springs, UT Code ch. 19.10). On the route side, the federal standard fixes the surface: "The running slope of walking surfaces shall not be steeper than 1:20. The cross slope of walking surfaces shall not be steeper than 1:48", and anything steeper than 1:20 is by definition a ramp (2010 ADA Standards §403.3, glossary). Within a site, "at least one accessible route shall connect accessible buildings, accessible facilities, accessible elements, and accessible spaces that are on the same site", with an exception only where the only means of access is "a vehicular way not providing pedestrian access" (§206.2.2); and "at least 60 percent of all public entrances shall comply with 404" (§206.4.1).
- Source: City of Saratoga Springs, UT, Code ch. 19.10 *Hillside Development Ordinance* — https://www.saratogasprings-ut.gov/DocumentCenter/View/702/1910-Hillside-Development — T1; US Access Board, *2010 ADA Standards for Accessible Design* — https://www.access-board.gov/ada/ — T1.
- Class: CODE REQUIREMENT (both halves; jurisdiction-flagged for the slope bands)
- Scope: any site with relief; the accessible-route rule applies wherever accessibility is required
- Confidence: High; Medium for the transfer of 15 %/30 % as general buildability limits (they are this city's, though they are common values)
- Grid translation: The host grid has no terrain, so carry `slope_class` per tile ∈ {`0–14.99 = BUILDABLE`, `15–29.99 = RESTRICTED`, `≥30 = PROTECTED`} and derive `buildable_mask = setback_envelope ∩ slope_class < RESTRICTED ∩ sun_envelope (SC-16)`. Accessible-route budget: 1:20 means 20 m of run per 1 m of rise = 40 tiles per metre of level change; per declared level change between site arrival point and entrance, require ≥40 tiles of route (and ≥41.7 tiles equivalent for 1:48 cross-slope drainage logic where the route doubles as a swale). Report `route_slope_compliant` per required connection, and `entrance_accessible_share ≥ 0.60` of public entrances. Flag `graded_site` whenever the plan cuts a `RESTRICTED` tile — that is the pre/post map the ordinance demands.
- Exceptions / failure mode: Retaining walls and cut/fill do not remove the class, they relocate the problem, and the ordinance's exception for ≥30 % slopes is deliberately narrow. Also, on a grid without section the *platform* is invisible: an agent may produce a "flat" plan that is physically a stepped section — so declare the platform strategy as an attribute (e.g. `single_platform`, `stepped:N`, `ramp:N`) rather than pretending the ground is level. Failure symptom: 100 % of a slope-restricted site drawn as buildable, or an entrance reached by a 1:8 "walk".

### SC-18 Give the site an explicit drainage and soft-surface budget
- Rule: Decide the site's surface split (building / paved / soft / water) as numbers before designing, then hold open space, drainage and tree cover against an impervious ceiling. Runoff and watercourse protection are the usual reason a site's coverage cap is tighter than its building cap.
- Evidence: "Impervious cover" is the accepted measurable indicator, defined to include "any surface in the landscape that [water] cannot pass through", and the effect is quantified: degraded stream conditions at 10–15 % watershed imperviousness, and "the size of one-hundred-year floods … can potentially double in watersheds with impervious cover levels greater than 20–30 percent" (NEMO/University of Delaware ch. 2). The regulatory definition that produces those numbers already counts hard surfaces, gravel areas, paths and courts, and building projections, as impervious (Sanford UDO App. A, "Impervious Surface"). Planning guidance expects drainage, waterways, flood risk and drainage capacity to be in the site inventory, and asks "Are there opportunities for flood alleviation? Net environmental gain?" among the looking-forward questions (NDG ¶41, "Looking forward" box).
- Source: NEMO Program, University of Delaware, *Nonpoint Source Education and Management Manual*, ch. 2 "Impervious Cover" — http://nemo.udel.edu/manual/chap2web.pdf — T2; Sanford, NC UDO Appendix A — T1; *National Design Guide*, Jan 2021 — T1.
- Class: FACT (the measured imperviousness thresholds and per-land-use figures; the site budget is the action taken from them)
- Scope: universal where runoff is managed on or from the site; thresholds are catchment-specific
- Confidence: High for the definitions and the direction of the effect; Medium for the exact 10–15 % / 20–30 % bands (research-derived, jurisdiction-dependent in application)
- Grid translation: Classify every tile of the site as `building | paved | soft | water | unpaved_gravel` (the last three per the Sanford definition count `paved`/`gravel` as impervious), then report `impervious_pct`, `soft_pct`, and `site_water_capacity_tiles` (swales, basins, permeable setts). Validation: `impervious_pct ≤ cap` (cap from the jurisdiction, else flag as `UNCITED`); and where the site drains to a watercourse, run the check at *watershed* rather than *site* scale and say so, because a compliant single site cannot fix a non-compliant catchment. Cross-check against SC-04's coverage figure — the two must differ by the paved area, and if they do not, the classification is broken.
- Exceptions / failure mode: In arid places, imperviousness is not the main driver of harm (EPA's UHI chapter notes desert development may *raise* moisture via irrigation), and in combined-sewer urban areas the constraint is overflow volume, not infiltration. Failure symptom: an agent that treats "walkable" ground tiles as automatically soft, so a 400-m² asphalt forecourt reads as 0 % impervious.

### SC-19 Manage the microclimate the site adds: heat island at the surface, wind at the pedestrian
- Rule: Treat the site's materials and gaps as a climate instrument. Record the soft/shaded/reflective share against the site's paved share, and where the site is dense or tall, check that the layout does not create unusable wind at its own edges.
- Evidence: Measured magnitudes: "The annual mean air temperature of a city with one million or more people can be 1.8 to 5.4 °F (1 to 3 °C) warmer than its surroundings, and on a clear, calm night, this temperature difference can be as much as 22 °F (12 °C)"; the *surface* heat island is larger still — "Day: 18 to 27 °F (10 to 15 °C), Night: 9 to 18 °F (5 to 10 °C)" — with the atmospheric heat island peaking at night ("Night: 12.6 to 21.6 °F (7 to 12 °C)"); the causes listed are low-albedo urban materials, long-wave radiation "obstructed by objects, such as neighboring buildings" (urban canopy / sky view factor), "reduced vegetation … [which] reduces the natural cooling effect from shade and evapotranspiration", and waste heat (US EPA, *Reducing Urban Heat Islands: Compendium of Strategies — Urban Heat Island Basics*). Wind criteria from a planning authority: "Wind Comfort Standard is an hourly mean wind speed for each wind direction, with probability of exceedance less than 5 % per annum … measured between 6am and 10pm (equivalent to 292 hours per annum), of equal to or less than: 4 metres/second for sitting areas, 6 metres/second for standing areas, 8 metres/second for walking areas", with a safety standard of "an annual hourly maximum peak 0.5 second gust wind speed … of 24 meters per second" (City of Sydney pedestrian wind report restating Sydney DCP 2012 §2).
- Source: US EPA, *Reducing Urban Heat Islands: Compendium of Strategies, Ch. 1 Urban Heat Island Basics* (draft; municipal-hosted copy) — https://media.alexandriava.gov/docs-archives/tes/eco-city/info/10=ecctf=meeting4=epa-reducing=urban=heat=islands=ch=1.pdf — T1; City of Sydney, *Environmental Wind Speed Measurements* (Appendix G, wind-tunnel report stating DCP 2012 criteria), 2022 — https://www.cityofsydney.nsw.gov.au/-/media/corporate/files/projects/policy-planning-changes/your-feedback-on-proposed-changes-to-planning-controls-for-hunter-street-and-pitt-street-sydney/documents/appendix-g-pedestrian-environmental-wind-report.pdf — T1.
- Class: FACT (measured UHI magnitudes and causes; the pedestrian-wind bands quoted with them are one authority's assessment criteria, see Scope)
- Scope: UHI applies to any developed site; the wind bands bind where tall/large massing is possible
- Confidence: High for the measured UHI magnitudes and causes (US EPA compendium, cited); Medium for the wind bands as general design targets (they are assessment pass/fail criteria for one city, and they presuppose wind-tunnel or CFD data the grid cannot produce); Low for any per-tile m/s claim (UNCITED — cannot be computed on this grid)
- Grid translation: Report `soft_tile_share`, `paved_low_albedo_share`, `canopy_shadow_tiles` and `sky_view_proxy = open_tiles_within_r / total_tiles_within_r` around each outdoor seating tile (r = 20 tiles = 10 m) — a plan-only proxy for the UHI drivers EPA names. For wind: on a 2D grid you cannot compute gusts, so use two structural proxies and mark them as proxies — (a) `gap_alignment`: a `walkable` corridor more than 8 tiles wide, aligned within 22.5° of the prevailing aspect and running between two long blank façades, is an acceleration channel (flag it); (b) `corner_exposure`: door and seating tiles within 6 tiles downwind of a sharp building corner need mitigation. Any claim of m/s at a tile is `UNCITED — cannot be computed on this grid`; the correct output is "this layout requires a wind assessment", not a number.
- Exceptions / failure mode: In cold climates the same channel that overheats in summer is the asset that flushes summer heat *only* if it is off the winter wind; and a shaded, tight plan that suppresses wind can worsen winter heating and summer overheating simultaneously. Failure symptom: a "green" site plan with 5 % soft share and 400 m² of dark paving called "plaza", or an agent quoting 6 m/s from a plan.

### SC-20 Set the section from the enclosure ratio: height and street width are one decision
- Rule: Where a street or square is being formed, its height-to-width ratio is a design parameter with published good ranges. Choose the ratio, then derive either the height for the given width or the width for the given height — do not set the two independently.
- Evidence: Published dimension bands: "The distance between frontages in residential streets typically ranges from 12 m to 18 m, although there are examples of widths less than this working well. There are no fixed rules but account should be taken of the variety of activities taking place in the street and of the scale of the buildings on either side" and the typical widths by street type — mews 7.5–12 m, residential street 12–18 m, high street 18–30 m, boulevard 27–36 m, square 18–100 m (Manual for Streets §5.4.2 and Fig. 5.3). The enclosure rule and its ratio table: "Enclosure is the relationship between the height of the buildings across a space, and the dimension of the space itself. Taller building heights and a more built up building line both increase the enclosure. Different degrees of enclosure influence how people use different spaces" (NDG ¶27), with Table 5.1 maxima/minima: minor streets e.g. mews 1:1.5 – 1:1, typical streets 1:3 – 1:1.5, squares 1:6 – 1:4.
- Source: DfT/DETR, *Manual for Streets*, 2007 — T1; *National Design Guide*, Jan 2021 — T1.
- Class: HEURISTIC (the source itself says "there are no fixed rules"; the bands are guides to be traded against daylight and wind)
- Scope: street-forming and square-forming sites; irrelevant to a detached building that forms no space
- Confidence: High for the published bands; Medium for their transferability outside UK residential practice
- Grid translation: Since height is not on the grid, carry `assumed_height_m` per façade (storeys × declared floor-to-floor) and report the **D/H ratio** across each formed space: `D = frontage_to_frontage_tiles / 2 tiles-per-m`, `H = assumed_height_m`. Then evaluate against the bands: a 24–36-tile (12–18 m) residential street with a 10-tile-high (5 m) façade gives 1:2.4, inside the 1:1.5–1:3 "typical street" range; a 40-tile (20 m) street with 10 m of height is 1:2; a 100-tile (50 m) square needs roughly 8.3–12.5 m of height to sit in the 1:4–1:6 band, and the same 50 m between frontages with 25 m of height is already 1:2, i.e. outside it. Emit a `formed_space` record per street/courtyard with `width_tiles`, `assumed_height_m`, `ratio`, `band_verdict`. Also flag `enclosure_gap` = a run of ≥12 tiles (6 m) of frontage where the building line recedes more than 6 tiles — the MfS/NDG failure of the "more built-up building line".
- Exceptions / failure mode: Ratios are the *aesthetic/scale* argument, not a light or wind guarantee (a 1:2 street can be permanently dark on the north side, and MfS itself warns of "overshadowing of surrounding areas" as a cost of taller buildings); the numbers also assume a pedestrian's view of the *entire* façade, which corners, trees and building recesses change. Failure symptom: an agent that treats 1:3 as a maximum permitted ratio, or that achieves a lovely ratio by narrowing the street and destroying the daylight next door.

### SC-21 Hold the street wall as a percentage rule, with a bounded amount of recess
- Rule: On urban frontages the build-to line is enforced as a share of the façade length, not as an average. Publish the percentage that must sit within the permitted distance of the street line, cap the recess depth, and treat the remainder as designed variation.
- Evidence: "For all buildings that are not subject to the provisions of paragraph (a) … Along wide streets, at least 70 percent of the aggregate width of street walls shall be located within eight feet of the street line and extend to at least the minimum base height … Up to 30 percent of the aggregate width of street walls may be recessed beyond eight feet of the street line, provided that any such recesses deeper than 10 feet along a wide street or 15 feet along a narrow street are located within an outer court"; along narrow streets, "at least 70 percent … within 10 feet"; for zoning lots of at least 40,000 sq ft or an entire block, "at least 50 percent … within 15 feet"; articulation "shall be permitted … provided such articulation does not exceed a depth or projection of 12 inches", and bay windows/façade recesses on "up to 50 percent of the aggregate width of street wall, at any level … provided that no such recess or projection exceeds a depth of three feet"; in R6B/R7B/R8B the rule is instead a *line-up* with adjacent buildings within 15 ft of the street line, within 25 ft of the subject building and over 35 ft high (NYC Zoning Resolution §23-431). Related height-side control: base-building height "between 10.5 metres and 80 % of the adjacent street right-of-way width (A), up to a limit of 24 metres", with additional height allowed "with a stepback of at least 3 metres, provided that the total height does not exceed 100 % of the adjacent street right-of-way width" (Toronto, §3.1.1).
- Source: NYC Zoning Resolution, Article II Ch. 3, §23-431 (print PDF of the official resolution text, last amended 5 Dec 2024) — https://zr.planning.nyc.gov/print/pdf/node/18037 — T1; City of Toronto *Tall Building Design Guidelines*, May 2013 — T1.
- Class: CODE REQUIREMENT (jurisdiction-flagged: New York's and Toronto's own percentages and depths; the percentage *form* is the transferable part)
- Scope: urban street-forming sites; do not apply on suburban, rural or open-campus frontages
- Confidence: High for the text quoted; Low for generalisation — many jurisdictions use a simple fixed setback instead of a percentage
- Grid translation: Convert the permitted offsets to tiles and round the *tolerance* down so a wall is never credited too generously: 8 ft = 2.44 m = 4.9 tiles → **4**; 10 ft = 3.05 m = 6.1 → **6**; 15 ft = 4.57 m = 9.1 → **9**; a 3 ft recess = 0.91 m = 1.8 → **1 tile**; 12 in = 0.30 m = 0.6 tile — **under one tile, unrepresentable**, record it as a limitation. Emit, per frontage: `street_wall_within_limit = Σ façade_tiles whose distance_from_street_line ≤ limit_tiles / frontage_tiles` and require ≥ 0.70 (≥ 0.50 on a whole-block site); cap any single recess deeper than 6 tiles (10 ft) on a wide street or 9 tiles (15 ft) on a narrow street unless it is declared an `outer_court`; cap total recessed width at 30 % (NYC) / 50 % for articulation no deeper than 1 tile. Add the Toronto proportion check as a height note: `assumed_base_height_m ≤ 0.8 × ROW_width_m`, i.e. on a 30-tile (15 m) street, ≤12 m.
- Exceptions / failure mode: Plazas, recessed entries and station forecourts legitimately break the line — but under NYC's own wording a deep recess must be an *outer court* with a public through-route, not a private void; and where an existing prevailing street wall is further back, the line-up rule (not the percentage rule) governs, which can *increase* the required setback. Failure symptom: a plan credited with a street wall it does not have (e.g. 70 % of the frontage measured against the building's own envelope rather than the street line), or a "recess" that is an unwatched wind tunnel.

### SC-22 Design the site for the phases it will actually be built in
- Rule: Assume the site will be built in more than one phase and give each phase its own working layout: a complete access and egress, a servicing connection, an interim landscape, a protected set of tiles the later phase will need, and no temporary condition that becomes permanent.
- Evidence: A planning authority defines the instrument and its trigger: "Phased Subdivision Application or Phased Site Plan Application (also known as a multi-phase development plan) — An application for subdivision or site plan approval in which the applicant proposes not to immediately subdivide or develop the property but to develop the property in one or more individual phase(s) over a period of time" (Sanford UDO App. A). The larger-site rule names the conditions and the deliverables: a Master Plan is required for developments "requiring new streets or parks; proposing multiple tall buildings; containing two or more construction phases; using shared servicing; and/or covering a site area larger than 2.0 hectares", and it must include "250 m and 500 m 'walkability' radii", the layout and dimensions of new streets, blocks, parks and open space, "important views and the shape of the skyline", heritage to be conserved, "size and dimensions of development parcels", and — per parcel — "general location of base buildings and tower footprints; setbacks between buildings and from streets, parks, and open space; proposed building heights and separation distances …; location of site servicing, vehicular circulation, and major utility connections including shared systems …; pedestrian and cycling connections through and around the tall building sites; and a phasing plan, schedule, and interim landscape plan" (Toronto, §1.2). Phasing is also an explicit criterion for industrial expansion design ("To best accommodate a future expansion at the north end of the …").
- Source: Sanford, NC UDO Appendix A — T1; City of Toronto *Tall Building Design Guidelines* §1.2, May 2013 — T1; City of Canby OR criteria response, 2024 — T1.
- Class: CODE REQUIREMENT (where a phased site plan is a defined submission type and the master-plan triggers are published)
- Scope: multi-parcel, multi-building or large sites; small single buildings need one line about future servicing capacity
- Confidence: High for the requirement and the deliverable list; Medium for the "2.0 ha" trigger as general (it is Toronto's)
- Grid translation: 2.0 ha = 20,000 m² = 80,000 tiles; 250 m = 500 tiles, 500 m = 1,000 tiles. Emit `phase_1_tiles` / `phase_2_tiles` / `reserved_tiles` as separate tile sets and validate per phase: (a) `phase_self_sufficiency` — every `blocked` wall tile of phase 1 that will face a reserved parcel must be a legal façade (no openings onto a neighbour's construction site, no shared-wall dependency that phase 1 cannot build alone); (b) `interim_use_defined` — reserved tiles carry a classification (`hardstand | soft | hold`), never "nothing"; (c) `service_capacity_at_full_build` — fire-apparatus reach (SC-09), curb cuts (SC-07) and loading berths (SC-08) computed for the final build-out, not phase 1; (d) no phase-1 route that only exists by crossing a phase-2 tile.
- Exceptions / failure mode: Phasing assumptions can be wrong in both directions; the risk is designing a temporary condition (a 40-year surface car park with a permanent façade behind it). Also, an approval may be *granted* for phase 1 only, so a plan that depends on phase 2 for a setback relief or an access is unapprovable. Failure symptom: phase 1 finished with the only fire access running through phase 2's site, or a "landscaped" interim that is asphalt in practice.

### SC-23 Never confuse site plan, footprint, floor plate and floor area — each has its own limit and its own tile count
- Rule: Keep four distinct quantities and never let one stand for another: the **site plan** (the whole bounded parcel and everything on it), the **footprint / building envelope** (the ground projection of the building, including its projections), the **floor plate** (one floor's area, which drives core distance, daylight depth and separations), and **floor area / FAR** (the sum of all floors against the site). Each is checked against a different control.
- Evidence: Definitions from adopted code: "**Site plan** — A scaled drawing and supporting text showing the relationship between lot lines and the existing or proposed uses, buildings, or structures on one or more lots, on which is shown (1) the existing and proposed conditions of the lot, including but not limited to topography, vegetation, drainage, flood plains, wetlands and waterways; (2) the location of all existing and proposed buildings, drives, parking spaces, walkways, means of ingress and egress …"; "**Building envelope** — the three-dimensional space occupied by a building, including all eaves, covered porches, breezeways and other portions of the building…"; "**Floor area** — the sum of the gross horizontal areas of the several stories of the building measured from the exterior faces of the exterior walls or from the center line of party walls", excluding basements, balconies/mezzanines, shafts and stairwells and enclosed porches, but including accessory buildings; "**Lot coverage** — the percentage of the area of a lot occupied by all buildings or other covered structures using the roof outline"; and FAR (Sanford UDO App. A). The floor plate is separately controlled in tall-building practice: "Limit the tower floor plate to 750 square metres", with separations "equal to the widest dimension of the tower floor plate" and a minimum of 25 m, and towers set "12.5 metres or greater from the side and rear" (Toronto §3.2.1–3.2.3), the stated reasons being daylighting, privacy, wind, shadow and sky view.
- Source: Sanford, NC UDO Appendix A — T1; City of Toronto *Tall Building Design Guidelines*, May 2013 — T1.
- Class: CODE REQUIREMENT (the adopted definitions each control is measured against, plus Toronto's published floor-plate and separation minima)
- Scope: universal; the specific caps are jurisdictional
- Confidence: High
- Grid translation: Four counters, reported separately: `site_tiles` (the whole extent), `footprint_tiles` (outer face of the envelope on the lowest buildable plane, including canopies/balconies that the code counts), `floor_plate_tiles[f]` per floor, and `floor_area_tiles = Σ floor_plate_tiles[f]` measured from the *outer face* of the envelope — on this grid that automatically includes internal walls, so state it, because the code definition (gross, from exterior faces) matches outer-face measurement while a "net room area" does not. Derived checks: `coverage = footprint/site` (SC-04), `FAR = floor_area/site` (SC-04), `floor_plate_m2 = floor_plate_tiles/4 ≤ cap` (750 m² = 3,000 tiles), `side/rear tower setback ≥ 25 tiles` (12.5 m), and `separation_tiles ≥ max(published_min_tiles, widest_floor_plate_dimension_tiles)` — the published minimum is 25 m (50 tiles) face-to-face, and it governs until the floor plate is wider than 50 tiles (25 m), after which the "equal to the widest dimension" rule takes over: a plate 70 tiles at its widest demands ≥70 tiles (35 m) between towers.
- Exceptions / failure mode: Every jurisdiction has its own exclusions (roofs, plant, parking floors, common areas, affordable-housing bonuses), so the *labels* transfer but the arithmetic does not; and the site plan includes things no building code counts (drainage, wetlands, egress routes) yet which bind layout. Failure symptom: an agent reporting "85 m² building" when it means footprint, and then applying a FAR allowance to the footprint instead of the summed floors.

### SC-24 Read the existing structures and the legible image of the place before proposing to remove anything
- Rule: Treat existing buildings, edges, routes and districts as information: what they fix (alignment, party wall, height, heritage), what they enable (an existing frame, an existing crossing, an existing frontage), and what their removal would take away from the place's readability. Retention and demolition must be an argued decision against the inventory, not a default.
- Evidence: National guidance puts "the existing built development, including layout, form, scale, appearance, details, and materials; local heritage … and local character" first in the site inventory, asks explicitly whether "embodied carbon [can be] reduc[ed] by retaining existing buildings", and requires new development to relate to "patterns of built form, including local precedents for routes and spaces and the built form around them, to inform the layout, grain, form and scale" (NDG ¶41–43, "Looking forward" box). Jacobs makes the protective case as an economic instrument: "One form of zoning for diversity is already familiar in certain city districts: controls against demolition of historically valuable buildings. Already different from their surroundings, these are zoned to stay different from them" (*The Death and Life of Great American Cities*, ch. 8 discussion of zoning for diversity). The legibility argument is classic: the city's public image is composed of **paths, edges, districts, nodes and landmarks** (Lynch's five elements, *The Image of the City*, pp. 46–84 — Paths 49, Edges 62, Districts 66, Nodes 72, Landmarks), and "a legible city would be one whose districts or landmarks or pathways are easily identifiable and are easily grouped into an over-all pattern".
- Source: *National Design Guide*, Jan 2021 — T1; Jane Jacobs 1961 — T3; Kevin Lynch, *The Image of the City*, MIT Press, 1960 (course PDF mirror: https://cus.ubt-uni.net/wp-content/uploads/2024/11/Kevin-Lynch-The-Image-of-the-City.pdf) — T3; City of Toronto §1.2 (heritage properties and Heritage Conservation Districts "to be conserved", and "important views and the shape of the skyline" among required master-plan content) — T1.
- Class: DESIGN PRINCIPLE
- Scope: universal on altered/redevelopment sites; empty-site effect is the same list minus "retain"
- Confidence: High for the requirement to record them; Medium for the causal claims (legibility → wellbeing, demolition controls → diversity)
- Grid translation: Carry existing structures as `blocked` tiles on their floors with `existing = true`, plus `party_wall` edges (a party wall is a hard constraint: it fixes the alignment, and the shared wall cannot be opened without the neighbour's structure being addressed), plus `edge | district | node | landmark` tags on site factors. Validation: (a) every demolition is recorded as a row with `reason` and `what_replaces_its_information` (which tile keeps the alignment, the frontage, the view); (b) `alignment_continuity` — new façade tiles on a frontage where an existing street wall exists must match its build-to line within 2 tiles unless declared; (c) `landmark_view_kept` — the sight line from a declared node/viewpoint tile to a landmark tile must not be crossed by new `blocked` tiles; (d) party-wall reuse credited in the wall-tile budget.
- Exceptions / failure mode: Legibility is a weak constraint against genuine hazards, and a retained structure can be the thing that prevents the correct layout (it blocks the only fire access, or sits in the flood channel). Lynch's elements also describe *perception*, which is culturally and individually variable, and the five-element schema was derived from three US cities in the 1950s–60s. Failure symptom: a plan that preserves a wall and therefore a bad layout, or one that keeps the "character" as a comment and not as tiles.

## Weak or contested

- **`Exploring Site Planning` (Bentley / Murray / Moyer) could not be found.** Not in Open Library (0 records for the exact title), not retrievable from publisher catalogues in this pass. The brief lists it as a T3 anchor for site-analysis method; this file substitutes the UK national guidance (NDG ¶41–43) and LaGro/Lynch & Hack for that function, and records the failure. Do not cite it until the edition is verified.
- **WHO environmental-noise guideline values (road traffic 53 dB Lden, 45 dB Lnight) were not verified.** The WHO publications page 404'd, the compendium PDF returned only compressed streams, and the NCBI Bookshelf table sat behind a browser check. The noise rules above therefore rest on the US federal land-use/aircraft-noise compatibility matrix (T1, read in full) plus a *qualitative* attenuation principle. Any road-traffic dB figure in a downstream skill file is `UNCITED — heuristic`, Confidence Low, until WHO or a national noise map standard is actually opened.
- **Right-to-light adequacy has no geometry.** The 20-year prescriptive period and the *Colls* "ordinary purposes of inhabitancy and business" test were verified in Law Com 356, but the popular "40-degree line"/"90-degree rule" back-of-envelope tests were *not* found in the report text read here and must not be attributed to it. Right-to-light is also being reformed-or-abolished proposals territory and is absent from most jurisdictions; the rule is scoped England/Wales.
- **Setback, FAR, coverage, loading, stack, fire-access and separation figures are all single-authority numbers.** NYC yards, Orem access spacing, Great Falls fire widths (an IFC restatement), Canby loading berths, Barnsley separations, Toronto floor-plate and separation caps, Saratoga slope classes, Sydney sun planes. Each is genuinely published *by that authority* — none is a general fact. Every use must be re-verified against the project's actual adopting code, and the agent should output the authority name with the number, always.
- **The 10–15 % / 20–30 % imperviousness thresholds are a single research tradition.** They appear via a University of Delaware extension manual that attributes them to "research in Delaware and elsewhere" and to Center for Watershed Protection work, without the primary study being cited in-line. Directionally robust; not a design limit to quote to a client.
- **Jacobs's small-blocks and border-vacuum claims are observational, not measured.** Strong, widely adopted design reasoning; but the causal chain from block length to street life is exactly the kind of claim the space-syntax literature has argued over for decades, and the elasticity evidence in Ewing & Cervero is mixed in sign on street-network design (grid indicators pointing both ways in Cervero & Kockelman 1997, as reported there). Use as design ordering, never as a forecast.
- **Wind comfort cannot be computed on this grid at all.** The 4/6/8 m/s bands and the 24 m/s gust are real published criteria, but they require boundary-layer data and either wind-tunnel or CFD results. The proxies in SC-19 (gap alignment, corner exposure) are this file's inventions, explicitly `ENGINEERING CONSTRAINT`-shaped heuristics: Confidence Low, and their only legitimate output is "a wind assessment is required", never a velocity.
- **The "2.5 × berth area truck court" figure is derived, not published** (SC-08) — computed from the Great Falls inside/outside turning radii (35/55 ft) as an order-of-magnitude manoeuvre allowance. `UNCITED — heuristic`, Confidence Low.
- **Sub-tile and unrepresentable quantities, listed so the skill does not fake them:** 12 in (0.305 m) façade articulation (ZR §23-431(d)) is under one tile; 1:48 cross slope (0.0104) is under one tile of height resolution; 13 ft 6 in fire-clearance height, 14 ft berth height, 75,000 lb surface capacity, DNL bands, dB NLR requirements, and every sun altitude — all are *attributes to tag*, not geometry to draw. Rounding direction must be stated per check (widths and separations round **up**, envelopes and setbacks round **down**).
- **Gaps I could not close:** (i) no USDOT/FHWA complete-streets or access-management primary text was retrievable (transportation.gov 403, FHWA page not opened), so curb-cut evidence rests on one city's standards; (ii) no verified source for the classic "site analysis inventory categories" list outside the NDG and unread textbooks; (iii) no verified per-jurisdiction FAR *values* (only the definition) — the file deliberately gives no district FAR number; (iv) no verified figure for drive-through queuing *duration* (drivers-hours), so stacking lengths here are regulatory minima, not demand-calculated.

Unverified-by-type note: this file supplies **no** dimensional standard for any building type. Every number in it is a *site* control (a setback, a separation, a spacing, a width, a berth, an hours-of-sun, a slope class, a percentage of a frontage) published by a named authority for all types in its district, and each must be re-verified against the project's jurisdiction and its adopted edition before it enters a rule set.
