# Core Principles

## Conventions

- Follow the language/framework idioms already used in the file you edit. Check neighboring files before choosing patterns, libraries, or structure.
- Never assume a library is available because it is well known; verify the project already uses it.
- Keep imports at the top of modules.
- Follow security best practices. Never log or commit secrets and keys.

## Comments and documentation

- Do not add code comments unless explicitly requested.
- Do not create `*.md` documentation files unless explicitly requested.

## Simplicity and scope

- Prefer direct, understandable implementations. Do not introduce services, databases, queues, event buses, generic repositories, facades that only forward calls, or other infrastructure without a demonstrated need.
- Do not optimize for scale the product does not have (multi-user sync, remote deployment, caching layers) unless scope changes.
- Preserve user data. Validate cross-references whenever data domains are split or recombined.
- Compatibility wrappers may exist during migration, but never two independent implementations of the same operation.

## Dead code and cleanup

- When removing a class, function, modifier, or pattern, remove every reference project-wide in the same change: call sites, templates, styles, string literals.
- Zero-delta duplicates (code identical to what it extends or wraps) are dead code; remove them instead of keeping both.
- Do not introduce a replacement unless the product requires it. If something is simply unused, delete it and stop.

## Verification

- After implementation, verify with commands appropriate to the touched boundaries: typecheck, tests, lint, production build.
- Choose verification by boundary: persistence/migration changes need read-back checks; engine changes need engine tests; template/style changes need markup lint if one exists.
- Report unrelated pre-existing failures separately; do not hide them or change unrelated systems just to make a legacy test pass.

## Decisions (ADR)

- 2026-08-26 - CAD plan system lives in `src/cad/` as a standalone pure-TS generator (types/spec/modules/floors/render/validate) rendered by the new Plans tab (`CadPlans.vue`); it does NOT touch origin assets, the blueprint data files, or the NPC layout. The 11-storey building is one architectural system: 4 m structural grid (44 x 22 m), 2.2 m clear central corridor, central core x16-28 with 4 lifts + stair SC-1 + MEP riser, wing stairs SC-A/SC-B whose strips are absorbed by L-shaped corner rooms, stacked bath modules and soil shafts on every guest floor. Renderer emits a complete standalone SVG sheet (poché, door swings, windows, dims in mm, grid bubbles, title block) mounted via v-html because `svgSanitizer.renderSvgInto` strips `<style>/<use>` that CAD linework relies on; content is first-party generated, never user input. QC gates: `tests/test-cad-layout.ts` (in npm test) validates geometry, connectivity BFS, stacking, fixture containment, door-on-edge and svg structure. Trade-off: plans are a drawing system, not walkable NPC geometry. Revisit trigger: gameplay needs to path NPCs through the CAD floors.
- 2026-08-24 — No undo/redo in the blueprint editor (owner decision). Destructive actions rely on confirm dialogs that must state the truth ("cannot be undone"); never reference Ctrl+Z. Safety net is per-mutation autosave via `saveBlueprintData` plus explicit confirms for delete/street-assign. Revisit trigger: user requests history after losing work.
- 2026-08-24 — Placed objects are rotation-only editable; every other detail renders read-only and inherits live from its origin asset. Asset color model = `defaultFillColor` + `defaultStrokeColor` (outline auto-derived from fill when unset; theme fallback `--asset-outline`). `defaultBgColor` removed along with instance-level fill/stroke overrides and `updateObjectProps`/`addAsset` dead paths. Revisit trigger: user asks for per-instance recoloring again.
- 2026-08-24 — Removed the unused CRUD facade layer (crud/npcSettings.ts deleted; list/get/create/update/delete wrappers across originAssets/floorPlan/tagManager trimmed to survivors actually called by UI: `getFloor`, object/floor mutations, tag `ensureTag`). UI talks to store modules directly; reintroduce wrappers only when a second consumer appears. Trade-off: less API surface vs. slightly longer import paths. Revisit trigger: a non-Vue consumer needs framework-free data access.
- 2026-08-24 — Walkable contract: `asset.walkable` is the MASTER "passable" switch. When true, engine ignores walkableGrid/tileEdges entirely (objectBlocksTile returns early) and the panel disables Doors & Edges. When false, per-tile grid governs. Flattened assets always reset to fully-blocked so authors paint passages deliberately (deny-by-default). Rotation rotates grid/states/edges/spots CW consistently (verified by harness). Revisit trigger: sub-tile collision precision is ever needed.
- 2026-08-24 — Economy v1 was prototyped (engine/economy.ts + HUD + localStorage) then removed the same day - too early for the product. Design is preserved in git history (search "Economy v1" in earlier commits): income = rate x active interacting guests, flat tip per visit, offline earnings at reduced rate with hard cap, strict save parser that discards malformed blobs. Revisit trigger unchanged: player asks what cash/goals are for, or a spending sink gets designed first.
- 2026-08-24 — Deleted the stale `blueprintData.json` snapshot. The four `src/blueprint-editor/data/*.data.ts` modules (served/saved via the dev-server `/__blueprint-data` middleware) are the ONLY persisted blueprint store; nothing ever loaded the json. `verify:assets` now parses originAssets.data.ts directly, so the AssetDef gate guards the live registry instead of a dead copy that had drifted (it still contained builtin assets absent at runtime). Trade-off: none - removing a zero-consumer duplicate. Revisit trigger: a production build gains a static-json persistence endpoint and needs a generated bundle again.
- 2026-08-25 — Auto-wall: tiles in the street ring (outer `streetWidthTiles`, default 8) are walkable ONLY on the floor designated by `layout.streetFloorId`; every other floor blocks them (hotel wall), derived from `isStreetTile` in `isTileWalkable` (`engine/npc/layoutBuild.ts`) with `streetFloorId` plumbed through `NpcCanvasBounds`, `SyncedCanvas`/syncedPayload, editor and game canvas providers. No `streetFloorId` set = legacy behavior (ring open everywhere). Perimeter walls are NOT persisted per floor - derived from `buildingArea()` so canvas/street resize propagates; interior walls stay hand-painted via floor `walkable.tileEdges`. Trade-off: NPCs cannot stand on sidewalks of non-street floors without an exception. Revisit trigger: gameplay needs exterior loitering or per-floor wall overrides.
- 2026-08-25 — Asset completeness gate narrowed: `assetSettingsIssues` flags only grid/state gaps while Passable is OFF; missing `tileEdges` and drawn-without-SVG no longer count as incomplete (edges are optional paint, drawn assets render via `fallbackShapeSvg`). No-op empty `tileEdges` purged from origin assets; Double Bed keeps real perimeter edges. Revisit trigger: authors want a reminder to replace shape previews with SVG art.
- 2026-08-25 - Painted wall edges stay in `FloorWalkable.tileEdges`; selection is transient `floorId` plus segment geometry and deletion writes through `updateFloor`. Trade-off: no stable per-wall id, but the existing persisted schema remains unchanged. Revisit trigger: wall metadata or multi-segment editing needs identity.
- 2026-08-25 - Sync payload derives object sizes: `buildSyncedObject` (`syncedPayload.ts`) fills missing or non-positive `w`/`h` from the origin asset via `assetSizeFor` (rotation-aware) because `serializeObject` persists placements without dimensions; fresh-boot game payloads previously synced undefined sizes so placed objects rendered invisible until a manual Sync Game. Full note: docs/adr/ADR-0001-sync-payload-derives-object-sizes.md. Trade-off: objects whose asset vanished from the registry sync as 0x0. Revisit trigger: placements start carrying authoritative sizes in the persisted schema.
- 2026-08-25 - Browser storage reduced to `blueprint-view-toggles` only. Removed `blueprint-editor-ui-state` (persisted floor/mode/selection ids dangled whenever git-tracked floor ids changed while per-machine localStorage did not - stale currentFloorId made `currentFloor` undefined and hid the editor floor switcher) and `blueprint-zoom-state` (wrote localStorage but read sessionStorage, so it never restored anything). Editor now opens deterministically on floor G / object mode with fit-to-screen; boot and reloadEditorData guards still fall back to the first floor on any stale id. Full note: docs/adr/ADR-0002-browser-storage-limited-to-visual-toggles.md. Trade-off: refresh no longer restores active floor, tool mode or selection. Revisit trigger: single-device session restore becomes important (fingerprint-gate any restored id against current data).
- 2026-08-25 - Wall box-select is mode-independent: Shift+drag from empty space selects walls in ANY editable mode (previously gated behind wall-paint mode, which users found illogical); Delete handles mixed object+wall selections in one confirm and one commit per store. Wall paint mode keeps left-drag = draw and drag-from-wall = select. Selected/pending walls render accent + dashed + thicker so marquee feedback matches object selection (live highlight under the drag box). Trade-off: plain empty-space drag still means "select objects" in normal modes and "draw" in wall paint - only Shift disambiguates walls everywhere. Revisit trigger: a unified marquee that selects objects and walls together in a single selection model.
